| 主题 | 状态 | 必须能答 | 笔记 |
| ---- | ---- | -------- | ---- |
| video/audio 标签 | ⬜ 待补 | canPlayType 为什么返回 maybe、原生播放的边界 | [[video标签与canPlayType]] |
| MSE（Media Source Extensions） | ⬜ 待补 | SourceBuffer 生命周期、appendBuffer 队列、buffered 管理与 eviction | [[MSE核心机制]] |
| MSE 手写最小播放器 | ⬜ 待补 | fetch 拉流 → demux → appendBuffer → 播放，全流程可运行 | [[MSE最小播放器-验证demo]] |
| WebCodecs | ⬜ 待补 | VideoDecoder 帧级控制 vs MSE 整段喂、什么场景值得用 | [[WebCodecs与MSE的边界]] |
| Web Audio API | ⬜ 待补 | AudioContext 时钟、为什么音画同步靠它而不靠 Date.now | [[WebAudio与音画同步时钟]] |

> 为什么这么设计：**video 标签是「整文件喂」→ MSE 是「分段喂」→ WebCodecs 是「逐帧喂」**，控制粒度逐层变细、门槛逐层变高。自研播放 SDK 的能力检测（isTypeSupport）就是在这三层里选路：浏览器支持 H265 硬解 → MSE；不支持 → WASM 软解；H264 统一走 MSE。
