# 04 · KV Cache：为什么不是 QKV Cache，也不是 O Cache

> **结论先行**：KV Cache 能成立，**根子上靠的是掩码自注意力的一条性质——历史 token 永远看不到未来**。既然看不到，新 token 的生成就不会改变历史 token 的注意力结果，历史 token 的 O、FFN 输出、乃至后面几十层的整条计算链路就都**不用重算**。于是每层把历史 token 的 **K 和 V** 存下来，新 token 只算自己的 QKV，逐层去查缓存即可。**为什么不存 Q**：Q 是一次性用品，用完就没人再用。**为什么不存 O**：O 是「我从别人那里拿回了什么」，而新 token 需要的是「你能给我提供什么」，那是 K 和 V。换个说法——**KV Cache 省掉的绝不只是两个线性变换，而是历史 token 的整条前向链路**。

## 一、先把一次前向走一遍

以「轩辕 养了 一只 黄色的 虎皮」为例：

| 步骤 | 做什么 |
| ---- | ---- |
| 1 | 分词器把输入切成 token |
| 2 | 每个 token 经**词嵌入**变成高维词向量（含语义） |
| 3 | 叠加**位置编码**（含顺序信息） |
| 4 | 经训练好的线性变换得到 **Q / K / V** |
| 5 | 每个 token 拿自己的 Q 去匹配**所有可见 token** 的 K（含自己） |
| 6 | softmax 得权重 → 对 V 加权求和 → 得到新向量 **O**（融合上下文） |
| 7 | 一组 QKV 不够 → **多头注意力** |
| 8 | 再接 **FFN** 做更深入的学习 |
| 9 | 注意力 + FFN = 一个 **block**，层层堆叠，最终预测下一个 token |

> 术语约定：注意力算完得到的新向量记作 **O**（以虎皮为例就是 O虎皮），O 再经 FFN 得到这一层的最终输出，然后进入下一层。

## 二、最笨的生成方式：每一步全部重算

已经输入 7 个 token「轩辕 养了一只黄色的虎皮 鹦鹉」，要预测第 8 个。

**笨办法**：把 7 个 token 全部重新送进去——

- 第一层重新算 7 个 QKV、重新做 attention、重新得 7 个 O、重新跑 7 次 FFN；
- 第二层再来一遍……一直到最后生成第 8 个 token；
- 而生成第 8 个之后，整个过程**再从头来一遍**。

> ❓ 这里面有没有重复工作？

## 三、关键性质：历史 token 看不到未来

回看掩码自注意力：像 GPT 这样的生成式大模型，**每个 token 只能看到自己和前面的内容，看不到后面**。

所以「虎皮」能看到「轩辕 养了 一只 黄色的 虎皮」，但**看不到后面的「鹦鹉」**——哪怕鹦鹉已经生成出来。

**推下去**：

1. 新 token 出现 → 不改变虎皮原来能看到的内容 → 输入关系没变；
2. ⇒ **O虎皮 不会变**；
3. ⇒ FFN 参数没变、输入没变 ⇒ **FFN 结果也不会变**；
4. ⇒ 同样适用于轩辕、养了、一只、黄色的；
5. ⇒ **鹦鹉出现后，前面 6 个历史 token 的 attention 与 FFN 结果全部还是原来的结果**。

> 既然完全一样，为什么还要重算？**历史 token 的计算完全可以省下来。**

### 3.1 反驳：那第二层怎么办？

第一层不重跑，第二层的输入（第一层 FFN 的输出）从哪来？

**答**：一个 token 第一次完整穿过 Transformer 时，**在每一层都会产生一份属于该层的 K 和 V**。模型 40 层，虎皮就有第一层的 (K,V)，第二层的 (K,V)……一直到第 40 层。

而新 token「鹦鹉」到第 20 层时，**真正需要的不是第 19 层的 O虎皮，也不是让虎皮重跑一遍 FFN，而是第 20 层已经算好的 K虎皮 和 V虎皮**——因为它要拿自己的 Q鹦鹉 去匹配这一层的 K，再读对应的 V。

> ✅ 所以：**第一次算 K/V 时就存下来**。第一层存第一层的历史 KV，第二层存第二层的，一直存到最后一层。

## 四、有了缓存之后，新 token 怎么走

以「鹦鹉」为例：

| 位置 | 做什么 | 不做什么 |
| ---- | ---- | ---- |
| 第 1 层 | 只算自己的 Q鹦鹉/K鹦鹉/V鹦鹉；用 Q鹦鹉 查询**已保存的** K轩辕…K虎皮（加上自己的 K鹦鹉）；按权重读取**已保存的** V + 自己的 V鹦鹉 → 得到新的 O鹦鹉；FFN 只处理 O鹦鹉 | 不重算 O轩辕、O养了、O一只、O黄色、O虎皮 |
| 第 2 层 | 同样：只算鹦鹉的 QKV，查询第 2 层缓存的历史 KV → O鹦鹉 → 跑一次 FFN | 不重跑历史 token |
| … | 一路跑到最后一层 | — |

**前面的 6 个历史 token 再也不用重新穿过整个 Transformer。** 计算量一下就小得多了。

被保存下来的这些历史 K 和 V，就是 **KV Cache**。

## 五、三个「为什么不」

### 5.1 为什么只缓存 K 和 V，Q 去哪了？

看「虎皮」这个 token：Q虎皮 是**虎皮自己做 attention 时**用的查询向量，它拿自己的 Q 去匹配历史的 K、算出 O虎皮 之后，**任务就完成了**。

- 以后「鹦鹉」来了，用的是 **Q鹦鹉**；
- 再来一个新 token，用的又是**那个新 token 自己的 Q**；
- **未来没有任何人会把 Q虎皮 再拿出来查一次。**

所以历史 Q 是**一次性用品，用完就扔**；而 K 和 V 不一样——未来每个新 token 都可能拿自己的 Q 来匹配 K虎皮、读取 V虎皮。

| 向量 | 含义 | 命运 |
| ---- | ---- | ---- |
| **Q** | 我现在想找什么 | 用完即弃 |
| **K** | 我这里有什么，**还要留着给未来匹配** | 缓存 |
| **V** | 我真正能提供什么，**还要留着给未来读取** | 缓存 |

> 这就是它叫 **KV Cache** 而不是 QKV Cache 的原因。

### 5.2 既然 O虎皮 都算出来了，为什么不缓存 O？

因为 V虎皮 和 O虎皮 **代表的不是一回事**：

| 向量 | 是什么 | 视角 |
| ---- | ---- | ---- |
| **V虎皮** | 虎皮这个 token **能给别人提供**什么信息 | 站在**别人**的角度 |
| **O虎皮** | 虎皮拿着自己的 Q 从大家那里**拿回来并汇总**的信息 | 站在**虎皮自己**的查询视角 |

现在「鹦鹉」要根据自己的 Q鹦鹉 判断「应该从虎皮这里读取多少」，它需要的是 K虎皮 和 V虎皮；O虎皮 是虎皮查询视角下的产物，**不是鹦鹉该直接拿来用的 value**。

> 🎯 **KV Cache 缓存的是 attention 计算之前的 K 和 V，不是最后的 O。**

## 六、它到底省了多少（这才是重点）

**表层理解**：用空间换时间——不必每次吐新 token 时为历史 token 重做那两个线性变换。

**真正的大头**：因为历史 token 看不到未来，新 token 出现不改变历史结果，于是——

- 历史 token 的 **Q** 不用重算；
- 历史 token 的 **attention** 不用重算；
- 历史 token 的 **O** 不用重算；
- 历史 token 的 **FFN** 不用重算；
- 甚至历史 token **后面几十层的整条计算路径**都不必重跑。

> 在 **decode 阶段**（模型一个 token 一个 token 正式往外生成时），**真正需要完整穿过几十层 Transformer 的，只有最新那一个 token**。历史 token 不再重新穿过模型，它们只以**每一层 KV Cache** 的形式留在那里，等待新 token 的查询。

没有 KV Cache 时，生成第 n 个 token 要对 n 个 token 跑满整个网络；有了它，每个新 token 只需**自己的一份** forward。这就是今天大语言模型能逐 token 高速生成的根本原因之一。

### 6.1 缓存有多大（工程视角补充）

KV Cache 的显存占用大致是：

$$\underbrace{2}_{K,V} \times n_{\text{layer}} \times n_{\text{kv\_head}} \times d_{\text{head}} \times n_{\text{token}} \times \text{bytes}$$

> 关键点：**它随 token 数线性增长，且每层都有一份**。公式里的 $n_{\text{kv\_head}}$ 也正是 [[06-长上下文与注意力变体\|MQA/GQA/MLA]] 想压缩的对象——减少 KV 头数就是直接减小缓存。

## 七、KV Cache 也救不了百万上下文

| 问题 | 说明 |
| ---- | ---- |
| **缓存爆炸** | 每层都有自己的一份 KV Cache，几十上百层之后，百万级上下文所需的存储空间非常庞大 |
| **计算量依然巨大** | 按标准注意力，任意两个 token 之间都要算注意力；上下文到百万量级，即便有 KV Cache，每个新 token 的计算量仍是天文数字（每个新 token 要和全部历史 K 做点积） |

> 光有 KV Cache 还不够，还需要新的办法——**现代大模型中形形色色的注意力计算**（下一期）。

## 一句话记忆卡

- 前提：**因果掩码 ⇒ 历史看不到未来 ⇒ 历史结果不会变**。
- 缓存单位：**每一层**各自的 K、V。
- 新 token：只算自己的 QKV，逐层查缓存。
- 不存 Q：一次性的查询。不存 O：O 是「我拿到的」，不是「我能给的」。
- 代价：显存随层数 × 上下文长度线性膨胀。
