# 03 · Transformer 到底是个啥：把结构图上的每个零件「推」出来

> **结论先行**：Transformer 结构图上那一堆名词，**没有一个是凭空出现的**——它们全是被前一个结构暴露出的新问题**逼**出来的。这条推导链是：要让每个 token 直接看其他 token → **自注意力（QKV）**；一套 QKV 覆盖不了多种关系 → **多头**；并行后顺序丢了 → **位置编码**；只会找信息不会消化 → **FFN**；层数深了梯度消失 → **残差连接（+ 归一化）**；生成时不能偷看未来 → **掩码自注意力**；解码器得知道原文说了啥 → **交叉注意力**。把这七步记住，整张图就不用背了。

## 〇、从 LSTM 留下的两个坑出发

| LSTM 的问题 | Transformer 的答案 |
| ---- | ---- |
| 必须一个 token 一个 token 顺序算，前一个没算完后一个不能开始 | **全部 token 并行**，矩阵运算一起完成 |
| 两个距离很远的 token 交换信息，要经过中间几十个 token 逐步传递 | **直接建立联系**，隔 1 个还是 100 个都一样 |

> 例：「……但他始终记得小时候养过的那只 **它**」中的「它」和很远处的「虎皮鹦鹉」直接相关，凭什么要绕一圈传话？

Transformer 出自 2017 年论文 **Attention Is All You Need**。

## 一、注意力：让每个 token 直接查看所有 token

人读句子时不会从头再分析一遍，而是**一瞬间扫过**前文，迅速注意到「它」和「虎皮鹦鹉」关系最强。让神经网络也这么干：句中每个 token 都去问一句——**这些词里哪些和我最相关？**

**例**：「轩辕 养了 一只 虎皮鹦鹉」正在处理「它」这个 token，模型算出关系权重：

| token | 权重 |
| ---- | ---- |
| 轩辕 | 10% |
| 养了 | 5% |
| 虎皮鹦鹉 | 70% |
| 其他 | 15% |

按权重把各 token 携带的信息**混合**起来：权重高多拿，权重低少拿。混合后「它」得到一个**新向量**——它已经不再是孤零零的词向量，而是**融合了上下文**（尤其是虎皮鹦鹉的信息）。

> 🎯 一句话定义注意力：**让当前 token 判断其他 token 对自己有多重要，然后重点读取重要的信息。**

### 1.1 QKV：怎么实现「查看」

要搜索，先得有**搜索关键词**。于是每个 token 准备三份向量：

| 名字 | 含义 | 类比 |
| ---- | ---- | ---- |
| **Q（Query）** | 我现在想找什么 | 搜索关键词 |
| **K（Key）** | 我这里大概有什么可供查询 | 网页标题/标签 |
| **V（Value）** | 我真正携带了哪些信息 | 网页正文 |

**流程**：

1. 当前 token 拿自己的 Q，挨个和其他 token 的 K 做**点积**，得到一个分数，分数越大越匹配。
2. softmax 把分数变成权重，就知道该关注谁、关注多少。
3. 用权重乘上各自的 V 再求和 → 得到当前 token 融合上下文后的新向量。

**示例分数**：Q·K(轩辕)=1.2，Q·K(绿色)=0.8，Q·K(虎皮鹦鹉)=6.8 → 虎皮鹦鹉更值得关注。

> ❓「凭什么保证 Q 和 K 刚好能匹配上？」→ **靠训练**。一开始胡乱匹配，训练中参数不断调整，Q/K 的匹配越来越贴近语言规律。

### 1.2 一个词向量怎么变出三个

把原来的几百维词向量分别经过**三个不同的线性变换**，得到 Q、K、V。三个变换的参数同样不用手工设计，训练中学出来。

### 1.3 论文里的公式：为什么要除以 √d

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

> 维度高了以后点积结果容易变得很大，过 softmax 会过于极端（趋近 one-hot），先缩小一点让训练更稳定。这就是那个 **$\sqrt{d_k}$**。

### 1.4 名字由来：Self-Attention

Q、K、V **全部来自同一句话**的 token——自己查看自己，叫 **self-attention（自注意力）**。若是一句话跟另一句话做注意力，就不是自注意力（下一节的交叉注意力就是）。

## 二、多头注意力：一套不够，就多来几套

同一句话里可能同时存在多种关系：

| 关系类型 | 例子 |
| ---- | ---- |
| 指代关系 | 「它」←「虎皮鹦鹉」 |
| 修饰关系 | 「绿色」←「羽毛」 |
| 动作关系 | 「轩辕」←「养过」 |
| 另一种关系 | 「养过」←「虎皮鹦鹉」 |

只有一套 QKV 很难同时兼顾。**那就同时做多组注意力计算**：第一组可能关注指代，第二组关注邻近词，第三组学到长距离关系，第四组学到别的模式。谁负责什么**不是程序员安排的**，是训练自己决定的——我们只负责给它多个不同的观察空间，最后把各头结果**拼接**成更丰富的表示。

> 这就是 **多头注意力（Multi-Head Attention）**。一个「头」= 一套独立的注意力计算。一个角度看不明白，就多个角度一起看。

原始 Transformer 用了 **8 个头**。

### 2.1 顺带解决的两件事

1. **不用逐步传话**——远距离 token 直接建立联系；
2. **所有 token 的 QKV 可以一起算**（大规模矩阵运算）→ **天然适合 GPU 并行训练**，这是后来模型能越做越大的重要前提。

## 三、并行的代价：顺序信息丢了 → 位置编码

RNN/LSTM 串行处理天然有序；并行计算把顺序抹掉了。

> 「轩辕养了鹦鹉」vs「鹦鹉养了轩辕」——同样三个 token，顺序不同，意思完全不同。但注意力只算相关性，**不处理顺序**。

**解法**：在每个 token 的词向量上再加一份**表示位置**的信息——第一个 token 加「位置 1」的编码，第二个加「位置 2」……模型收到的就不只是「这是哪个词」，还知道「它在什么位置」。

这就是 **position encoding（位置编码）**：原始 Transformer 用**正弦/余弦函数**生成，现在的大模型又发展出新方案（细节不在本期展开）。

> 一句话记住：**word embedding 告诉模型 token 的语义，位置编码告诉模型 token 的顺序。**

## 四、注意力只会「找信息」，还得有人「消化」→ FFN

**例**：「轩辕买了个黑色的苹果，花了 1 万多块钱」——这里的苹果是水果还是苹果公司？人一瞬间就知道：哪有卖一万多、还是黑色的水果。

把「苹果」的词向量简化为 4 个特征（0~1）：高价、黑色外观、水果属性、科技属性。

| 阶段 | 高价 | 黑色 | 水果 | 科技 | 说明 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 刚看到「苹果」 | 0 | 0 | 0.6 | 0.6 | 两种含义都可能有 |
| 过完注意力 | 0.9 | 0.9 | 0.6 | 0.6 | 从「黑色」「1万多块钱」拿回了线索 |
| 再过完 FFN | 0.9 | 0.9 | **0.1** | **0.95** | 组合研判：又贵又黑 ⇒ 不像水果，像电子产品 |

> 🔑 **分工**：注意力负责 token 之间**交换信息**（交流）；FFN 只看自己手里的信息，学习**特征之间的组合关系**（思考）。

到这里两个零件就能拼成一个单元：**多头注意力（交换信息）→ 前馈神经网络（消化加工）**，这就是 Transformer 的**基本单元**。

实际模型会垒很多层，一层比一层理解更深：原论文 **6 层**，现在的大模型动辄**几十上百层**。大模型的知识与能力，都藏在这些网络参数里。

## 五、网络一深就训练不动 → 残差连接

训练靠**反向传播**：预测产生误差 → 梯度从最后一层往前传 → 告诉前面的参数怎么调（本质是链式求导）。梯度一层层相乘不断变小，传到最前面时已非常微弱 → 前面的层收不到有效调整信号 → **梯度消失**。

### 5.1 一个「看起来很奇怪」的办法

把这一层的输入**直接加到输出上**：$$Y = F(X) + X$$

> 第一反应：直接把 X 加上去，结果不就被改了吗？

关键在于 **F 本身是训练出来的**。原来要完整训练出大写的 $F(X)$，加了 X 之后，训练目标变成**只需学「在原来的 X 基础上还差多少」**——这个「差多少」就是**残差**，所以叫**残差连接（Residual Connection）**。

### 5.2 真正厉害的地方在反向传播

求导后多出一个 **+1**：

$$\frac{\partial Y}{\partial X} = \frac{\partial F(X)}{\partial X} + 1$$

- 原来梯度只能走 F 这条复杂路径；
- 现在旁边多出一条**直接连接输入与输出的捷径**，它的导数恒为 **1**；
- 即便 F 这条路的梯度被削弱，梯度仍有一条更直接的路径往前传。**不能保证梯度永不衰减，但能大幅缓解**梯度消失。

前向传播时，原始信息也能沿捷径直接往后传，不必每层彻底重新加工一遍。

> 🛣️ 残差连接 = 给网络修了一条**高速公路**：前向传信息，反向传梯度。正因如此，Transformer 才能稳定堆到几十甚至上百层。

实际结构里残差通常还搭配**归一化**模块（LayerNorm），让训练更稳定 → 结构图上那个 **Add & Norm**。

## 六、最后一块拼图：把向量变成具体的词

原论文解决的是**机器翻译**，可拆成两步：**先读懂原文（Encoder）→ 再把译文写出来（Decoder）**。

### 6.1 Encoder（编码器）

就是前面搭好的那套：输入 → 词向量 → 加位置信息 → 一层层自注意力 + FFN。**每个 token 都能查看整句话的其他 token，包括它后面的内容**——这没问题，因为编码器的任务本就是理解一句**已经存在**的原文。

产出：每个 token 变成一组融合了整句上下文信息的向量。**编码器不生成 token**，它只把「原文是什么意思」编码进向量。

### 6.2 Decoder 的第一道纪律：掩码自注意力

解码器一个 token 一个 token 往外生成。训练时正确答案（整句译文）都在手上——预测「bug」时若能看到后面的「bug」，就等于**抄答案**。

**规则：只能看到自己和前面的 token，不能看后面。**

**做法**：计算注意力分数时，把后面位置的分数改成**一个极小的数**，过 softmax 后权重几乎变成 0（相当于被遮住）。这张遮挡叫 **mask**，加了 mask 的自注意力就是**掩码自注意力（Masked Self-Attention）**。

### 6.3 第二道：交叉注意力

但只看自己写出来的英文，解码器不知道原文说了什么。所以它要**一边写一边回头看编码器**：

| 谁 | Q | K / V |
| ---- | ---- | ---- |
| 自注意力 | 解码器自己 | 解码器自己 |
| **交叉注意力** | **解码器** | **编码器输出** |

> 要生成「八级」时，它的 Q 可能与原文「虎皮鹦鹉」对应的 K 高度匹配，于是把那里的 V 大量拿过来。

**解码器每层三步**：掩码自注意力（看看自己前面写了什么）→ 交叉注意力（回头看看原文）→ FFN（继续加工）。

### 6.4 蹦出词来

最后一个位置的向量接到输出层 → 给整个词表每个 token 打分 → softmax 变概率 → 概率最高的通常就是下一个 token（也可采样）。把新 token 接到末尾，继续预测下一个，**一个 token 一个 token 往外蹦**，直到生成结束符。

> 现在以 GPT 为代表的大模型和最早的 Transformer 已经不完全一样（只用 Decoder 那一半），这点后面再展开。

## 七、总复盘：每个零件都是被问题逼出来的

| # | 遇到的新问题 | 被逼出来的零件 |
| ---- | ---- | ---- |
| 1 | LSTM 要逐个 token 传话、只能串行 | **自注意力**（每 token 直接查看其他 token） |
| 2 | token 该查看谁？怎么算权重？ | **Q / K / V**：Q 发起查询，K 被匹配，V 真正传信息 |
| 3 | 一句话里有指代、语法、语义等多种关系，一套 QKV 不够 | **多头注意力** |
| 4 | 并行计算后先后顺序消失 | **位置编码** |
| 5 | 注意力只负责找信息，信息拿回来还得加工 | **前馈神经网络 FFN** |
| 6 | 层数一深，梯度消失、原始信息易丢 | **残差连接**（+ 归一化） |
| 7 | 生成时不能偷看未来 | **掩码自注意力** |
| 8 | 解码器需要读取编码器内容 | **交叉注意力** |

> 💡 这些一个个小改造组合起来，就形成了今天**几乎所有大语言模型**背后的基础架构。看懂结构图的正确姿势不是背名词，而是**沿着问题一路往下推**。

## 八、留给下一期的思考题

现在的大模型上下文动不动就 **100 万 token**，如果两两计算注意力，$$O(n^2)$$ 的计算量将非常恐怖。有没有办法优化？→ **下一期：KV Cache / 注意力变体与长上下文**。
