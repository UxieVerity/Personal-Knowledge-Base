# 数组去重（Unique）

> **结论：数组去重 = 去掉重复元素。** 首选手写：**`[...new Set(arr)]`**——O(n)、一行、支持 NaN（SameValueZero 语义）。面试完整答案按复杂度递进给：**Set（O(n)）→ filter+indexOf（O(n²)）→ reduce+includes（O(n²)）→ 双层循环+splice（原地，O(n²)）→ 排序相邻（O(n log n) 但改顺序）**。三个必答的坑：① **NaN**——`indexOf` 用 `===`（`NaN !== NaN`）去不掉，`Set/includes` 用 SameValueZero 能去；② **对象数组**——Set 按引用去重，不同对象不去重，要按 id 去重用 `Map`；③ **原地 vs 副本**——splice 版改原数组。

> 可运行验证：[[数组去重-验证脚本.js]]（Node 实测：五种方法对比 / NaN 陷阱 / 对象数组 Map 按 key / 原地去重 / 10 万元素性能）

---

## 1. 背景：什么时候需要去重

- 接口数据合并（多页拉取、多源汇总）后重复
- 数组元素去重后渲染（下拉选项、标签列表）
- 统计去重数量（`new Set(arr).size` 即唯一数）

> 为什么这么设计：JS 的 `===` 比较有两个历史包袱——**`NaN !== NaN`**（IEEE 754 规定 NaN 不等于任何值）和**对象按引用比较**（两个内容相同的对象 `===` 为 false）。所以"去重"这种看似简单的事，在不同方法下行为不一样，**考的就是你对比较语义的掌握**。

## 2. 标准实现（面试手写版）

### 2.1 Set（最推荐，一行）

```js
const unique = arr => [...new Set(arr)];
```

### 2.2 filter + indexOf（经典，但 NaN 有坑）

```js
const unique = arr => arr.filter((v, i) => arr.indexOf(v) === i);
// 只保留"第一次出现"的元素：indexOf 返回首次下标，等于自己下标才保留
```

### 2.3 reduce + includes

```js
const unique = arr => arr.reduce((acc, v) => (acc.includes(v) ? acc : [...acc, v]), []);
```

### 2.4 双层循环 + splice（原地去重，改原数组）

```js
function unique(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) { arr.splice(j, 1); j--; }   // 删掉重复，j-- 回退
    }
  }
  return arr;
}
```

### 2.5 Map 按 key 去重（对象数组高频变体）

```js
const uniqueByKey = (arr, key) => [...new Map(arr.map(o => [o[key], o])).values()];
// 对象数组按 id 去重：Map 的 key 是 o[key]，重复 key 覆盖 → 留最后一个
```

| 方法 | 复杂度 | 改原数组 | NaN | 对象数组 | 面试定位 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| Set | O(n) | 否 | ✅ 去 | 按引用（不去） | **首选** |
| filter+indexOf | O(n²) | 否 | ❌ 不去 | 按引用 | 经典，答坑 |
| reduce+includes | O(n²) | 否 | ✅ 去 | 按引用 | 函数式写法 |
| 双层循环+splice | O(n²) | **是** | ✅ | 按引用 | 原地版 |
| 排序相邻 | O(n log n) | 否(副本) | ✅ | 不行(排序比较怪) | 备选，改顺序 |
| Map 按 key | O(n) | 否 | — | **按 id 去重** | 对象数组专用 |

## 3. 实测数据（数组去重-验证脚本.js）

```
[A1-A5] 五种方法 → 都是 [1,2,3,4,5]（基本输入全对）
[B1] Set:        [null,1,2]  ← NaN 去掉了（SameValueZero）
[B2] filter+idx: [1,2]       ← NaN 没去掉！（indexOf 用 ===，NaN!==NaN 查不到自己）
[B3] reduce+inc: [null,1,2]  ← includes 用 SameValueZero，能去
[C1] Set(按引用):  [1,2,1]   ← 三个对象都留（引用不同）
[C2] Map(按id):   [1,2]      ← 按 id 去重，留第一个
[D1] splice 原地版: 原数组被改成 [1,2,3]  ← 注意副作用
[E1] 10 万元素: Set 0.5ms | filter+indexOf 1.4ms | 双层循环 2878ms（O(n²) 差距 5000 倍）
```

> 实测亮点：**双层循环 vs Set 差了约 5000 倍**（2878ms vs 0.5ms）——这就是为什么首选 Set，也是面试官问复杂度的原因。

## 4. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 去重最简单写法？ | `[...new Set(arr)]`，O(n) 一行 |
| NaN 能去重吗？ | `Set`/`includes` 能（SameValueZero），`indexOf` 不能（`===` 语义 NaN!==NaN） |
| 对象数组怎么去重？ | Set 按引用不去；按 id 用 `new Map(arr.map(o => [o.id, o]))` |
| splice 版有什么注意？ | 改原数组（副作用）；删除后 `j--` 回退防止跳项 |
| 排序去重为什么少用？ | 改变原顺序，且对象/混合类型排序比较有问题 |
| filter+indexOf 复杂度？ | O(n²)——每个元素 indexOf 都扫一遍；数据大时明显慢 |

## 5. 面试速记（30 秒版）

> **去重首选 `[...new Set(arr)]`（O(n)，支持 NaN）。** 经典题答法：**filter+indexOf**（`indexOf(v) === i` 只留首次）→ 但 NaN 去不掉（`===` 语义）；**reduce+includes** 能去 NaN（SameValueZero）。**对象数组**：Set 按引用不去重，按 id 用 **Map**。**splice 原地版**改原数组、删后 `j--`。实测：10 万元素 Set 0.5ms vs 双层循环 2878ms，差 5000 倍 → 别用 O(n²)。
