# 数组扁平化（Array Flatten）

> **结论：数组扁平化 = 把嵌套数组拍平成一层。** 核心就一个递归：`遍历每一项，是数组就递归拍平，否则 push`。两个关键升级点：① **指定层级** `depth`（`flat(depth)` 语义，不传默认全部拍平）——高频考点；② **空位处理**——`flat()` 跳过空位，手写 `forEach` 也跳过（`for` 循环不跳）。面试至少手写两个版本：**递归版**（思路清晰）和 **迭代版**（栈 + 逆序展开，不爆栈）。再问一句"能不能更优雅"——`reduce + concat` 一行版、`JSON.stringify` 正则版（仅纯数字数组）、`flat(Infinity)` 内置版，按需抛出来。

> 可运行验证：[[数组扁平化-验证脚本.js]]（Node 实测：递归/迭代/一行版输出对比 / 指定层级 / 空位处理 / 深层数组不爆栈 / JSON 正则版边界 / 性能）

## 1. 背景：什么时候需要扁平化

- 接口返回树形/嵌套数据（如目录树、多级菜单、评论楼中楼）需要拍平后遍历渲染
- 多维数组求和/统计：`[1,[2,[3]]]` 要算总得先拍平
- 框架里数组操作链：`map → flat` 组合（`flatMap` 就是 `map` + `flat(1)`）

> 为什么这么设计：数组天然可以嵌套（数组元素是任意值，包括数组）。**嵌套是合法的，但很多场景要"一层一层的值"**——于是语言内置了 `flat`，手写题考你的是**理解递归拆解嵌套结构**的能力，这跟深拷贝是同一类递归思维。

## 2. 标准实现（面试手写版）

### 2.1 递归版（最直观，先写这个）

```js
function flatten(arr) {
  const result = [];
  for (const item of arr) {
    if (Array.isArray(item)) {
      result.push(...flatten(item));   // 是数组 → 递归拍平后展开 push
    } else {
      result.push(item);               // 否则直接 push
    }
  }
  return result;
}
```

### 2.2 指定层级版（`flat(depth)` 语义，高频变体）

```js
function flattenDepth(arr, depth = Infinity) {
  if (depth <= 0) return arr.slice();          // 层级用尽 → 原样返回（浅拷贝）
  const result = [];
  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) {
      result.push(...flattenDepth(item, depth - 1));  // 每进一层 depth-1
    } else {
      result.push(item);
    }
  }
  return result;
}
```

| 点 | 作用 | 面试要点 |
| ---- | ---- | ---- |
| `depth <= 0` 早退 | 层数边界 | 不写会多拍一层，`flat(1)` 语义错误 |
| `arr.slice()` | 不改动原数组 | 返回副本，原数组保持嵌套 |
| `depth - 1` | 每递归一层减一 | 逐层控制，而非一次拍到底 |

### 2.3 迭代版（栈，不依赖递归深度）

```js
function flattenIter(arr) {
  const stack = [...arr];          // 栈初始化为展开的原数组
  const result = [];
  while (stack.length) {
    const item = stack.pop();      // 取出栈顶
    if (Array.isArray(item)) {
      stack.push(...item);         // 是数组 → 展开推回栈（后进先出保持顺序）
    } else {
      result.push(item);           // 否则收集
    }
  }
  return result.reverse();         // pop 是倒序取的 → 最后 reverse
}
```

| 点 | 作用 | 面试要点 |
| ---- | ---- | ---- |
| `stack.push(...item)` | 数组展开进栈 | **展开而非递归**，靠栈模拟调用栈 |
| `result.reverse()` | 恢复顺序 | `pop` 从尾部取 → 收集的是倒序，最后反转 |
| 不递归 | 深层不爆栈 | 深拷贝/扁平化的递归版遇超深数组会 `RangeError`，迭代版不会 |

> **高频追问：为什么不用 `result.unshift()` 省掉 reverse？**
> 逻辑上可行（`unshift` 每次插到头部 → 天然正序，return 时不用 reverse），**但 `unshift` 是 O(n) 的头部插入**——每次要把后面所有元素后移一位，N 次插入总复杂度 **O(n²)**；而 `push` 尾部追加摊还 O(1)，最后 `reverse` 一次 O(n)，总 **O(n)**。
> 实测（本机 Node，浅层嵌套）：10 万元素 `push+reverse` 6.6ms vs `unshift` 3158ms（**差 ~480 倍**）；50 万元素 57ms vs 133,664ms（**差 ~2300 倍**）。差距随规模爆炸增长。
> **面试结论：宁可多写一个 `reverse`（O(n)），也绝不用 `unshift`（O(n²)）。**

### 2.4 迭代版 + 指定深度（高频变体，面试常追问）

> 递归版指定深度是**参数传递**（`depth - 1` 传给子调用）；迭代版没法传参，就把深度**塞进栈元素**——栈存「值 + 剩余深度」二元组：

```js
function flattenDepthIter(arr, depth = Infinity) {
  if (depth <= 0) return arr.slice();                    // 边界：深度用尽 → 副本
  const stack = arr.map(item => [item, depth]);          // 每个元素带上剩余深度
  const result = [];
  while (stack.length) {
    const [item, d] = stack.pop();                       // 取出「值 + 它剩的深度」
    if (Array.isArray(item) && d > 0) {                  // 还是数组且深度没用完 → 展开
      for (const child of item) stack.push([child, d - 1]);  // 子项深度减一
    } else {
      result.push(item);                                 // 否则收集（含 d<=0 的数组本身）
    }
  }
  return result.reverse();                               // pop 倒序 → 反转
}
```

| 点 | 作用 | 面试要点 |
| ---- | ---- | ---- |
| `[item, depth]` 二元组 | 深度跟着元素走 | 不同嵌套层级的元素剩余深度不同，**不能全局一个 depth** |
| 展开时 `d - 1` | 深度传递 | 递归版的参数传递 → 迭代版塞进栈元素，两者等价 |
| `d <= 0` 直接收集 | 边界语义 | 第 `depth+1` 层保留为数组，与递归版 `depth <= 0` 早退一致 |
| 不递归 | 超深 + 指定深度两全 | 递归版「超深会爆栈」，这个版本两个坑都避开 |

> 实测 `[G1-G3]`：与递归版 `flattenDepth` 输出完全一致；`[G4]` 1 万层也不爆栈。

> 为什么还要会迭代版：递归版面试 30 秒写出来，但追问"**如果数组有 1 万层呢**"——递归爆栈（本机实测约 1.25 万层），迭代版用显式栈扛住。**考的是你知道递归的代价和替代。**

## 3. 一行版 / 内置版（加分项）

```js
// ① reduce + concat（只拍一层）
const flat1 = arr => arr.reduce((acc, v) => acc.concat(v), []);

// ② 递归 reduce（全部拍平）
const flatAll = arr =>
  arr.reduce((acc, v) => acc.concat(Array.isArray(v) ? flatAll(v) : v), []);

// ③ 内置 flat（2020+，V8 递归实现）
arr.flat(Infinity);

// ④ JSON 正则版（仅纯数字/无空位/无字符串"[object"陷阱）
JSON.parse('[' + JSON.stringify(arr).replace(/\[|\]/g, '') + ']');
```

| 版本 | 拍平层数 | 坑 |
| ---- | ---- | ---- |
| `reduce + concat` | 1 层 | 不是递归，深层拍不平 |
| 递归 reduce | 全部 | concat 每次新建数组，性能一般 |
| `flat(Infinity)` | 全部 | **2020+ 内置；注意 V8 是递归实现，超深嵌套（实测 10 万层）会爆栈** |
| JSON 正则版 | 全部 | 元素含 `[]` 字符的字符串会坏（如 `"[a]"`），只适合纯数字 |

## 5. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 扁平化核心代码？ | 递归：遍历，是数组递归拍平后展开 push，否则直接 push |
| 怎么指定层级？ | `depth` 参数，每进一层 `depth-1`，`depth<=0` 早退返回副本 |
| 递归版会爆栈吗？ | 会——本机约 1.25 万层；深层用迭代版（栈） |
| 空位怎么处理？ | `flat()` 跳过空位；`forEach` 也跳过，`for...of` 不跳过 |
| 与 `flatMap` 关系？ | `flatMap(fn) === arr.map(fn).flat(1)`，只拍一层 |
| JSON 正则版能用于生产吗？ | 不能——只适合纯数字数组，字符串含 `[]` 就坏 |

> 面试总结：**"递归版先写，追问层级加 `depth`，追问深层用迭代版（栈），最后补一句 `flat(Infinity)` 是内置标准答案。"** 这条回答链覆盖 90% 的追问方向。

## 6. 面试速记（30 秒版）

> **扁平化 = 递归拆解嵌套。** 核心：遍历，是数组就递归拍平后 `...` 展开 push，否则 push。**升级 1：层级**——`depth` 参数逐层减一，`<=0` 早退返回副本；**升级 2：爆栈**——超深数组递归 `RangeError`，改**迭代版（栈 + 逆序 reverse）**。加分：`reduce + concat` 一行（只拍一层）、`flat(Infinity)` 内置（2020+，但 **V8 递归实现、超深同样爆栈**）、JSON 正则版（仅纯数字）。**空位**：`flat`/`forEach` 跳过。
