# 串行并发控制

> **结论：串行 = 一次只执行一个，前一个完成才启动下一个（并发 = 1）。两种经典实现——`async/await for...of`（最直观）和 `reduce` 链式（Promise 风格）。** 对比并发池（限制并发 N）：串行严格保序但耗时 = N×单任务；并发池结果仍保序但更快（耗时 ≈ N×单任务/并发）。实测：串行 5 任务×30ms = 169ms，并发 2 = 106ms。
>
> 可运行验证：[[串行并发控制-验证脚本.js]]（Node 实测：for-of 串行 / reduce 串行 / 并发池 / 耗时对比）

---

## 1. 一句话定义（背诵版）

**串行 = 把 N 个异步任务排成一队，一次跑一个，前一个 resolve 才启动下一个。**

| 实现 | 写法 | 特点 |
| ---- | ---- | ---- |
| **async/await for...of** | `for (const t of list) results.push(await t())` | 最直观，可 try/catch |
| **reduce 链式** | `list.reduce((chain, t) => chain.then(t), Promise.resolve())` | 纯 Promise，无 async 也能用 |
| 并发池（对照） | 滑动窗口 N 个 worker | 并发 > 1，结果仍保序 |

## 2. 两种实现（面试手写版）

### 2.1 async/await for...of

```js
async function serial(list) {
  const results = [];
  for (const t of list) {
    results.push(await t());   // await 阻塞 → 严格串行
  }
  return results;
}
```

**为什么 for...of 而不是 forEach**：`forEach` 不能 await 暂停（回调里 await 只暂停回调，不暂停外层循环）——`list.forEach(async t => { await t() })` 会**并发**执行，不是串行。**for...of 配合 await 才能真串行**。

### 2.2 reduce 链式

```js
function serial(list) {
  return list.reduce((chain, t) =>
    chain.then(res => t().then(v => { res.push(v); return res; }))
  , Promise.resolve([]));
}
```

**为什么 reduce 能串行**：每次回调返回一个新 Promise 作为下一次的 `chain`，前一个 `.then` 完成才执行下一个任务——**天然把「上一个的结束」接成「下一个的开始」**。

## 4. 并发池（对照，滑动窗口）

```js
async function pool(list, limit) {
  const results = new Array(list.length);
  let index = 0;                          // 原子递增取任务
  const workers = Array.from({ length: Math.min(limit, list.length) }, async () => {
    while (true) {
      const i = index++;
      if (i >= list.length) break;
      results[i] = await list[i]();       // 按索引写 → 保序
    }
  });
  await Promise.all(workers);
  return results;
}
```

**为什么结果保序**：每个任务结果写 `results[i]`（按索引），不是 push——和 Promise.all 同理（见 [[手写题/Promise链式与all-race]]）。**并发控制的关键**：`limit` 个 worker 同时跑，每个 worker 循环取任务，`index++` 保证任务不重复。

## 5. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 串行怎么写？ | `for...of + await`（或 reduce 链式） |
| 为什么 forEach 不行？ | forEach 回调里的 await 不阻塞外层循环 → 变并发 |
| reduce 怎么串行？ | 每次返回新 Promise 作为下次 chain，上一个结束 = 下一个开始 |
| 并发池怎么限流？ | N 个 worker + `index++` 取任务 + `results[i]` 保序 |
| 串行 vs 并发池怎么选？ | 依赖前一个结果 / 严格顺序 → 串行；能并行且控并发 → 池 |
| 串行耗时？ | N×单任务（并发池 ≈ N×单任务/并发） |

## 6. 面试速记（30 秒版）

> **串行 = 一次一个，前一个 resolve 才跑下一个。** 两种实现：**`for...of + await`**（await 阻塞循环，真串行；`forEach` 不行因为回调 await 不阻塞外层）和 **reduce 链式**（每次返回新 Promise 当 chain）。**并发池对照**：N 个 worker + `index++` 取任务 + `results[i]` 按索引写保序，限流且结果有序。选型：**依赖前一个结果 → 串行；能并行且控并发数 → 池**。
