# 观察者模式 + 单例模式

> **结论：观察者 = Subject 持有 Observer 列表，状态变化时 `notify` 全部观察者（直接关联、强耦合）。** 单例 = 全局只创建一个实例，三种实现：**静态属性版**（`if (!_instance) _instance = new X()`）、**闭包版**（IIFE 私有 instance）、**防 new 版**（构造器返回已存在实例）。实测：观察者 attach/detach/notify 全通，单例三种实现都恒返回同一实例。
>
> 可运行验证：[[观察者-单例-验证脚本.js]]（Node 实测：观察者通知/移除 + 单例三实现）

---

## 1. 一句话定义（背诵版）

| 模式 | 核心 | 一句话 |
| ---- | ---- | ---- |
| **观察者** | Subject → Observer 列表 | 状态变，直接 notify 所有观察者（强耦合） |
| **单例** | 全局唯一实例 | 不管怎么拿，永远同一个对象 |

## 2. 观察者模式（面试手写版）

```js
class Subject {
  constructor() { this.observers = []; this.state = null; }
  attach(obs) { this.observers.push(obs); return this; }   // 添加观察者
  detach(obs) { this.observers = this.observers.filter(o => o !== obs); return this; }
  setState(s) { this.state = s; this.notify(); }           // 状态变 → 通知
  notify() { this.observers.forEach(o => o.update(this.state)); }  // 通知全部
}
class Observer {
  constructor(name) { this.name = name; }
  update(data) { /* 收到通知的处理 */ }
}
```

实测：
```
[A1] attach 两个观察者 → 都收到 ["观察者A:新状态","观察者B:新状态"]  ✅
[B1] detach 一个 → 只剩另一个 ["观察者B:再变"]                     ✅
```

**核心**：观察者模式 = **Subject 直接持有 Observer 引用**，状态变化时逐个调 `update`。Subject 知道「有谁在听」——这是它和发布订阅的根本区别。

## 3. 观察者 vs 发布订阅（必考对比）

| 维度 | 观察者（Observer） | 发布订阅（Pub/Sub） |
| ---- | ---- | ---- |
| 关系 | **Subject 直接持有 Observer** | 中间有**事件总线**（broker） |
| 耦合 | **强**（subject 知道观察者） | **弱**（发布者不关心谁在听） |
| 触发 | `notify()` 通知所有观察者 | `emit(事件名)` 广播 |
| 典型 | Vue2 响应式（**Dep 通知 Watcher**） | EventBus / Node EventEmitter / 消息队列 |

> **一句话**：观察者 = 目标直接喊观察者（点名）；发布订阅 = 目标往广播站喊（不点名）。Vue2 的 `Dep`（每个响应式属性一个）就是观察者模式——依赖收集时 `dep.addSub(watcher)`，触发时 `dep.notify()`。

## 4. 单例模式（面试手写版，三种）

### 4.1 静态属性版（最常用）

```js
class Singleton {
  static getInstance() {
    if (!Singleton._instance) Singleton._instance = new Singleton();
    return Singleton._instance;
  }
}
```

### 4.2 闭包版（实例完全私有）

```js
const getInstance = (() => {
  let instance = null;
  return function () {
    if (!instance) instance = { ... };
    return instance;
  };
})();
```

### 4.3 防 new 版（构造器返回已有实例）

```js
class Singleton {
  constructor() {
    if (Singleton._instance) return Singleton._instance;  // 已存在 → 返回旧实例
    Singleton._instance = this;
  }
}
```

实测：
```
[D1] getInstance 两次 → s1 === s2 true  ✅
[E1] 闭包版两次 → c1 === c2 true        ✅
[F1] new 两次 → n1 === n2 true          ✅ 构造器返回旧实例
```

**防 new 版原理**：`new` 时如果构造器返回**对象**，用返回值而非 this（[[手写题/new]] 的规则）——所以 `return Singleton._instance` 能让 new 也拿到单例。

## 5. 单例实战场景

| 场景 | 为什么单例 |
| ---- | ---- |
| 配置中心 | 全局唯一配置，任何模块读同一份 |
| 事件总线 | `EventBus.getInstance()` 保证全局一个总线（**发布订阅常配单例**） |
| 连接池 / Logger | 资源只初始化一次（避免重复建连/重复初始化） |
| 状态管理 | Vuex/Pinia 的 store 本质是单例 |

> **单例的争议**：单例 = 全局状态，**测试难隔离**（模块间共享状态互相污染）。现代框架倾向依赖注入（DI）替代——测试时注入 mock。面试提一句「知道单例的局限」是加分项。

## 7. 面试速记（30 秒版）

> **观察者 = Subject 直接持有 Observer 列表，状态变 notify 全部（强耦合）。典型：Vue2 的 Dep→Watcher。** 和发布订阅的区别：**观察者点名通知（subject 知道谁在听），发布订阅走事件总线（解耦）**。**单例三实现**：静态属性 `if(!_instance) _instance=new X()`、闭包 IIFE 私有 instance、防 new（构造器 return 已有实例，利用「new 返回对象用返回值」规则）。实战：配置中心 / 事件总线（常配单例）/ 连接池。**局限**：全局状态测试难隔离 → 现代用 DI。
