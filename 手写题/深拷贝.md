# 深拷贝（Deep Clone）

> **结论：深拷贝 = 递归复制对象的所有层级，副本与原对象完全独立（改副本不影响原对象）。** 基础版就一个递归：`原始值直接返回 → 对象则逐 key 递归复制`。但两个关键升级面试必考：① **循环引用**——不加保护会无限递归爆栈，用 **WeakMap 登记已复制对象**（先登记再递归）解决；② **特殊类型**——`Date/RegExp` 要单独处理，函数一般按引用保留（但挂了自定义属性时有坑，见 §2.3）。**`JSON.parse(JSON.stringify())` 不是万能深拷贝**：丢 `undefined`/函数/`Symbol`、`Date` 变字符串、`NaN` 变 `null`、正则变空对象。
>
> 可运行验证：[[深拷贝-验证脚本.js]]（Node 实测：深浅拷贝对照 / 循环引用爆栈与 WeakMap 解法 / 特殊类型 / 原型保留 / 性能 / JSON 序列化的坑）

## 1. 背景：为什么要深拷贝

- 对象是**引用类型**：`const b = a` 只是复制引用，`a`、`b` 指向**同一个对象**，改一个另一个跟着变。
- 浅拷贝（`Object.assign` / 展开 `{...obj}`）只复制**第一层**：嵌套对象仍是共享引用（实测 `[B1]`）。
- 深拷贝：把**每一层都复制**，得到完全独立的新对象——常用于状态管理（Vuex/Pinia 里改数据前先拷贝）、配置快照、跨线程传参。

> 为什么这么设计：浅拷贝是"复制地址"，深拷贝是"复制内容"。JS 没有内置深拷贝（`structuredClone` 是 2022 年才有的新 API），因为**"深到什么程度"没有统一答案**（函数要不要拷？原型要不要保？环怎么办？）——所以考手写，考的是你**知不知道边界**。

## 2. 标准实现

### 2.1 基础版（递归，能处理纯数据对象/数组）

```js
function deepClone(obj) {
  if (obj === null || typeof obj !== 'object') return obj;   // 原始值直接返回
  const result = Array.isArray(obj) ? [] : {};
  for (const key of Object.keys(obj)) {
    result[key] = deepClone(obj[key]);                       // 递归每一层
  }
  return result;
}
```

### 2.2 进阶版（WeakMap 处理循环引用 + 特殊类型 + 原型）

```js
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (map.has(obj)) return map.get(obj);                     // ① 已复制过 → 直接返回副本（打破环）
  let result;
  if (obj instanceof Date) result = new Date(obj);
  else if (obj instanceof RegExp) result = new RegExp(obj.source, obj.flags);
  else if (Array.isArray(obj)) result = [];
  else result = Object.create(Object.getPrototypeOf(obj));   // ② 保留原型（instanceof 正确）
  map.set(obj, result);                                      // ③ 先登记再递归（关键！）
  for (const key of Object.keys(obj)) {
    result[key] = deepClone(obj[key], map);
  }
  return result;
}
```

### 2.3 追问版：函数挂了自定义属性怎么办（守卫顺序的坑）

上面两版的守卫 `typeof obj !== 'object'` **会连函数一起拦截**（`typeof fn` 是 `'function'` 不是 `'object'`）→ 函数直接返回**原引用**。函数没状态时无所谓，但函数挂了自定义属性（缓存 / 计数器 / 静态配置）就踩坑：**副本和原函数共享这些属性，改一个动两个**（实测 `[H1][H2]`）。修复 = 函数分支放在守卫**之前**：

```js
function deepCloneV2(obj, map = new WeakMap()) {
  if (typeof obj === 'function') {                           // 先拦函数（守卫之前！）
    if (map.has(obj)) return map.get(obj);                   // 函数自引用 fn.self = fn 也要防环
    const fn = function (...args) { return obj.apply(this, args); };  // 包装：调用转发原函数
    Object.setPrototypeOf(fn, obj);                          // 原型链指向原函数
    Object.defineProperties(fn, Object.getOwnPropertyDescriptors(obj)); // 复制自有属性
    map.set(obj, fn);                                        // 先登记再递归
    for (const key of Object.keys(obj)) {
      fn[key] = deepCloneV2(obj[key], map);                  // 属性值是对象时也深拷贝（如 cache Map）
    }
    return fn;
  }
  // ……后面与 2.2 完全相同（守卫 → Date/RegExp/Array → Object.create → map.set → 递归）
}
```

要点：**包装函数转发调用**（函数体本身闭包无法复制，能复制的是"可调用 + 自有属性"）；`getOwnPropertyDescriptors` 连 getter/setter 一起带过去；函数属性值若是对象要继续递归才真正独立。

**箭头函数的第二个坑（追问的追问）**：V2 用 `function` 包装，克隆出来的箭头函数**凭空多了 `prototype`、可以被 `new`**——原箭头 `new` 抛 `TypeError`，副本却能正常构造，行为语义变了（实测 `[I1][I2]`）。而词法 `this` 恰好无害：箭头函数的 `this` 在定义时捕获，`obj.apply(this, args)` 改不动它，转发调用结果一致。修正 = 按 `obj.prototype === undefined` 区分（箭头/方法简写/bound 都没有 `prototype`）：

```js
let fn;
if (obj.prototype === undefined) {
  fn = (...args) => obj(...args);              // 箭头包装：保持"不可 new"语义
  Object.defineProperty(fn, 'name', { value: obj.name, configurable: true }); // 包装后 name 变空，恢复
} else {
  fn = function (...args) { return obj.apply(this, args); };  // 普通函数：保持可 new
  Object.setPrototypeOf(fn, obj);
}
```

> 为什么这么设计：判断依据不是"是不是箭头函数"（语法上无法检测），而是**行为特征** `prototype === undefined`——箭头函数、对象方法简写、`bind` 的产物都不可构造，这一条全部覆盖。深拷贝的原则在这里体现为：**副本的行为面必须与原对象一致**（能 new 与否、name、原型链），丢任何一项都是语义漂移。

**闭包函数（追问的终点）：状态根本拷不了。** 函数能被复制的只有"可调用 + 自有属性"（`Object.keys(fn)` 能看到的那部分），而闭包变量存在函数的 **`[[Environment]]`（词法环境）**里——**JS 没有任何 API 能枚举或访问它**。所以 V3 的包装对闭包函数只是"调用转发"：副本一调用，还是走**原函数的 `[[Environment]]`**，状态完全共享（实测 `[J1][J2]`——克隆版 `++` 到 3，原函数 `getCount()` 立刻也是 3，双向互通，副本根本不独立）。

对照 `[J3]` 很说明问题：同样是私有状态，**挂在函数属性上**（`inc.count`）就拷得动、克隆后独立；**藏在闭包里**就拷不动。面试可以这样收口：

> **闭包函数无法被真正深拷贝**——这不是手写版的能力缺陷，是语言层面的限制（`[[Environment]]` 不可观测，`structuredClone` 干脆连函数都拒绝拷）。所有"深拷贝函数"的实现（包装 / 串行化）都只能复制自有属性；闭包状态要么接受共享，要么一开始就别用闭包存——把状态挂到属性上（`fn.count`）或放进对象里，才可拷。反过来说，**"私有状态藏闭包"和"状态可被复制"在 JS 里不可兼得**，这就是闭包实现真正私有变量的设计代价。


| 点 | 作用 | 为什么关键 |
| ---- | ---- | ---- |
| `map.has(obj)` | 检测循环引用 | `a.self = a` 时递归会无限循环，先查表返回已复制的副本 |
| **先 `map.set` 再递归** | 登记时机 | 必须先登记当前对象，否则 `a.self` 递归到 `a` 时查不到 → 还是爆栈 |
| `Object.create(getPrototypeOf(obj))` | 保留原型 | `{}` 会丢 `Player.prototype`，`instanceof` 变 false |
| `instanceof Date/RegExp` | 特殊类型 | 直接赋值会得到共享引用的 Date/RegExp |
| WeakMap 而非 Map | 弱引用 | 拷贝完原对象可被 GC，WeakMap 不阻止回收 |

> 为什么用 WeakMap：深拷贝是个"一次性"操作，用完后 `map` 就没用了。**WeakMap 的键是弱引用**——原对象被回收时，WeakMap 里的条目也跟着消失，不会造成内存泄漏。这是 WeakMap 和 Map 最核心的区别，面试官常在这追问。

## 4. JSON 序列化深拷贝的坑（高频对比题）

```
[G1] undefined/函数被丢弃
[G2] Date 变字符串 | 正则变空对象 {} | NaN 变 null
```

| 数据 | `JSON.parse(JSON.stringify(x))` | 手写 deepClone |
| ---- | ---- | ---- |
| `undefined` / 函数 / `Symbol` | ❌ 被丢弃 | ✅ 保留（函数按引用） |
| `Date` | ❌ 变字符串 | ✅ 保持 Date |
| `RegExp` | ❌ 变 `{}` | ✅ 保持 |
| `NaN` / `Infinity` | ❌ 变 `null` | ✅ 保持 |
| 循环引用 | ❌ 直接抛 `TypeError` | ✅ WeakMap 处理 |
| 原型 | ❌ 丢 | ✅ 保留 |

> 面试总结：**"JSON 深拷贝适合纯数据（接口返回的 JSON），一旦对象里有函数/Date/循环引用就得手写。"** 2022 年后的新答案：`structuredClone(obj)` 是浏览器/Node 内置的深拷贝，支持循环引用和 Date，但**不支持函数**。

## 6. 面试速记（30 秒版）

> **深拷贝 = 递归复制每一层。** 基础版：`原始值返回 + 对象逐 key 递归`。三个升级点：**循环引用用 WeakMap**（先登记再递归，遇环返回副本）、**Date/RegExp 单独处理 + Object.create 保原型**、**函数挂自定义属性的坑**——守卫 `typeof !== 'object'` 会连函数一起拦 → 返回原引用、属性共享，追问版把函数分支放守卫之前；箭头函数再追问一层：`function` 包装会让副本可被 `new`，按 `prototype === undefined` 用箭头包装。**闭包函数是终点：状态在 `[[Environment]]` 里无 API 可达，拷不了（只能复制自有属性）。**JSON 序列化不是万能**：丢 undefined/函数、Date 变字符串、NaN 变 null、循环引用报错——只适合纯数据。函数一般保留引用。新 API `structuredClone`（2022+）支持环和 Date 但不支持函数。
