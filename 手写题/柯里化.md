# 手写柯里化

> **结论：柯里化 = 把「一次接收 N 个参数」的函数，变成「分次接收参数、齐了才执行」的函数。** 核心判断：**当前参数够 `fn.length` 个 → 直接执行；不够 → 返回新闭包继续收集**。实测：逐个/一次/混合传参都正确，占位符版本（`f(1, _, 3)(2)`）也跑通。柯里化的本质是**用闭包持有已收集参数**——每次 `cAdd(1)` 生成一个新闭包，把 `[1]` 存进闭包环境。
>
> 可运行验证：[[柯里化-验证脚本.js]]（Node 实测：逐个/一次/混合传参 / 参数不足返回函数 / 占位符 / 参数复用 / this 透传）

---

## 1. 一句话定义（背诵版）

**柯里化 = 分次传参，凑够就执行。**

```js
function curry(fn, arity = fn.length) {
  return function curried(...args) {
    if (args.length >= arity) {           // 参数够了 → 执行
      return fn.apply(this, args);
    } else {                              // 不够 → 返回闭包继续收集
      return (...more) => curried.apply(this, args.concat(more));
    }
  };
}
```

## 2. 核心机制（面试逐句讲）

| 部分 | 说明 |
| ---- | ---- |
| `arity = fn.length` | 目标参数个数 = 原函数形参个数（`fn.length` 不数 rest/默认参数） |
| `args.length >= arity` | **够了就执行**——柯里化的终止条件 |
| `args.concat(more)` | **已收集参数 + 新参数** 拼接，交给下一次判断 |
| `curried.apply(this, ...)` | this 透传（实测 F1） |

**为什么用闭包**：`args` 被返回的函数引用，每次调用 `cAdd(1)` 就创建一个持有 `[1]` 的新闭包。柯里化 = **闭包三大用途之一（分次捕获参数）**，见 [[JS闭包与作用域-面试速记]]。

## 4. 为什么这么设计

- **为什么参数够就执行**：柯里化的契约是「分次传参，最终凑齐」。`fn.length` 是「还差几个」的天然度量，凑齐 = 执行。
- **为什么每次返回新函数**：每次调用只补一部分参数，返回的新函数持有「已收集的部分」——这是闭包的自然应用。`cAdd(1)` 是「还差 2 个参数」的函数，`cAdd(1)(2)` 是「还差 1 个」的。
- **为什么有占位符**：有些参数想「跳过」留到后面填（如 `f(1, _, 3)(2)`）。占位符用 `Symbol` 表示（唯一，不会和真实参数冲突）——和手写 call 用 Symbol 防覆盖同理。
- **实际价值**：**参数复用**（预置配置：`const info = log('INFO')` 后只管传消息）、**惰性求值**（分步准备）、**函数组合**（配合 compose）。

## 5. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 柯里化是什么？ | 分次传参、齐了执行——把 N 元函数变 N 次 1 元调用 |
| 怎么判断执行时机？ | 当前参数 ≥ `fn.length`（原函数形参个数） |
| 为什么需要闭包？ | 已收集参数要跨多次调用保存，只能靠闭包 |
| 占位符怎么实现？ | Symbol 占位，合并时把后续参数填进 `_` 位置 |
| 柯里化和偏函数区别？ | 柯里化固定「一次一个/多个直至凑齐」；偏函数任意预置一部分（bind 就是） |
| 实际价值？ | 参数复用（预置配置）、惰性求值、配合 compose 做函数组合 |

## 6. 面试速记（30 秒版）

> **柯里化 = 分次传参凑齐执行。** 核心：`args.length >= fn.length ? fn(...args) : (...more) => curried(...args, ...more)`。**闭包持有已收集参数**（闭包三大用途之一）。**加分**：占位符版本（`f(1, _, 3)(2)`，用 Symbol 占位）；**应用**：预置配置复用（`const info = log('INFO')`）。和偏函数区别：柯里化按形参凑齐，bind 是任意预置。
