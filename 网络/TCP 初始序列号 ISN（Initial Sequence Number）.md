#### TCP 初始序列号 ISN（Initial Sequence Number）

> **seq 不是从 0/1 开始顺序递增，而是随机生成初始值，之后再顺序累加。**

##### 1. ISN：连接一开始的 seq（三次握手 SYN 里的 x、y）

客户端 SYN 的`seq=x`，服务端 SYN 的`seq=y`，这个**x 和 y 是随机生成的初始序列号 ISN**，**不是 0，不是 1，不是上一个连接结束后的数字直接继续用**。

##### 为什么不能固定从 0 开始？

- 网络中可能有**旧连接延迟的残留数据包**（迟到的老 TCP 分片）。
- 如果每次连接 ISN 都固定 = 0，旧连接迟到的数据包 seq=100，会被新连接当成合法数据，造成数据错乱。

> 随机 ISN 用来区分不同 TCP 连接，避免旧报文干扰新连接。

> 注意：不是完全真随机，老系统简单随机；现代操作系统是**基于时间 + 哈希生成伪随机 ISN**，防 ISN 预测攻击。

##### 2. 连接建立之后：seq 就是严格顺序递增

连接建立成功以后，seq 就按字节顺序往上加：

1. SYN 占 1 个序号，ISN=x，发送完 SYN，下一次发送的 seq 就是 `x+1`
2. 如果发送 100 字节业务数据，本次 seq=x+1，下一次 seq = (x+1)+100
3. FIN 也消耗 1 个序号

#### ISN（初始序列号）取值范围

seq 字段是 **32 位无符号整数**IETF Datat...。 ✅ **协议层面理论范围：`0 ~ 4294967295`（\(2^{32}-1\)）**

> 一共约 43 亿个可能值，**0 和最大值都允许出现**，协议没有禁止 0 作为 ISN。 序列号是模 \(2^{32}\) 运算，超过 4294967295 就回绕到 0 继续算IETF Datat...。

> ⚠️注意：**不是操作系统会从 0 开始顺序取，只是协议允许这个区间内任意值**。

##### 1、RFC793 早期算法（古老实现）

原始规范：维护一个 32 位虚拟时钟，**每 4 微秒 +1**，完整一轮循环约 **4.55 小时**。

```
ISN = 这个持续递增的时钟计数器
```

特点：ISN 整体单调上涨，不是真随机；攻击者可以预测，后来被废弃。

##### 2、现代 Linux / Windows / BSD（RFC1948 / RFC6528）算法腾讯云

伪代码：

```
// time_counter：依然保留时间递增基底
// hash_val：基于【源IP、源端口、目的IP、目的端口 + 系统秘密密钥】加密哈希得到32位随机偏移
ISN = (time_counter + hash_val) & 0xFFFFFFFF;
```

- 结果仍然落在完整 32 位空间 `0 ~ 4294967295`，**不会人为裁剪到某个子区间**，抓包能看到高位很大、也可能出现很小的值，包括 0（概率极低）CSDN博...。
- `hash_val` 让**四元组不同，ISN 偏移不同**，防止攻击者猜序列号做 RST 劫持攻击。
- `time_counter` 保证：同一四元组快速重连，新 ISN 总体大于旧 ISN，规避旧延迟报文干扰新连接。

> 重点：**没有限定 “必须大于某个最小值”，没有 1000~10000 这种小范围，整个 32 位空间都可以命中**。
