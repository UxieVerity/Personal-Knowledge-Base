# TCP 三次握手（建立连接）+ 四次挥手（断开连接）

> TCP 是**全双工**：两边各自都有发送、接收通道，读写可以独立关闭。

[[TCP 初始序列号 ISN（Initial Sequence Number）]]

> 相关：[[TLS12和TLS13的区别]] —— 网络链顺序：TCP 三次握手 → TLS 握手 → HTTP 请求
## 🤝三次握手 —— 建立连接（Client 主动连 Server）

目的：**双方确认自己和对方的发送、接收能力都正常，协商初始序列号 ISN**

1. **① SYN（客户端→服务端）** 客户端发起连接，`SYN=1，seq=x`（x 是客户端随机 ISN）

> 含义：我想和你建立连接，我的初始序号是 x

2. **② SYN+ACK（服务端→客户端）** 服务端收到，回复同步 + 确认，`SYN=1，ACK=1，seq=y，ack=x+1`（y 是服务端随机 ISN）

> 含义：收到你的请求；我这边也要同步，我的序号 y；我期待下一个收到 x+1

3. **③ ACK（客户端→服务端）** 客户端回复确认，`ACK=1，ack=y+1`

> 含义：收到你的同步，期待下一个收到 y+1 ✅ **连接建立完成，双方可以传输业务数据**

> 小细节：第三次握手的 ACK 报文**可以携带业务数据**，前两次不能带数据。

状态流转：

- Client：`CLOSED → SYN_SENT → ESTABLISHED`
- Server：`LISTEN → SYN_RCVD → ESTABLISHED`

## 👋四次挥手 —— 断开连接（全双工，两边可以分别关闭）

> 重点：**TCP 是全双工，一方关闭只是不再发送数据，但还可以接收对方剩下的数据**，所以要 4 次。 假设**客户端主动关闭连接**

1. **① FIN（客户端→服务端）** `FIN=1，seq=u` 客户端没有数据要发了，发送 FIN。

> 含义：我这边不再给你发数据（客户端写通道关闭） 客户端状态：`ESTABLISHED → FIN_WAIT_1`

2. **② ACK（服务端→客户端）** `ACK=1，ack=u+1` 服务端收到 FIN，回复确认。

> 注意：**此时只是确认收到关闭请求，服务端还可以继续向客户端发剩下的数据！** 服务端状态：`ESTABLISHED → CLOSE_WAIT` 客户端收到 ACK：`FIN_WAIT_1 → FIN_WAIT_2`

👉 到这里：**客户端不能发，但是还能收服务端发来的数据**

3. **③ FIN（服务端→客户端）**`FIN=1，seq=v` 等服务端把自己剩余数据全部发送完毕，服务端也关闭自己的写通道，发出 FIN。 服务端状态：`CLOSE_WAIT → LAST_ACK`
4. **④ ACK（客户端→服务端）**`ACK=1，ack=v+1` 客户端回复确认。

- 客户端：进入 **TIME_WAIT**（必须等待 2MSL 时间才彻底 CLOSED）
- 服务端收到 ACK 后，立刻变成 `CLOSED`

等待 2MSL 目的：保证第④步 ACK 能到达服务端；如果 ACK 丢包，服务端会重传 FIN，客户端还能再次回复 ACK。

> ⚠️面试高频：为什么挥手是 4 次，握手可以 3 次？ 握手时服务端的 **SYN + ACK 可以合并成一个报文**，所以 3 次； 挥手时，收到 FIN 后的 ACK，和自己业务做完才发的 FIN**不能合并**，中间有可能还要传输数据，所以分成两个报文，一共 4 次。
