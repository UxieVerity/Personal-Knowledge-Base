# TLS1.3 AEAD + ECDHE

一句话概括：**ECDHE 负责安全协商出会话密钥，AEAD 负责加密 + 完整性校验，两者是 TLS1.3 核心安全组件，TLS1.3 已经强制只用这套组合，废弃旧的密码套件**。

## 1. ECDHE：密钥交换（干什么：双方在不安全网络协商出共同的会话密钥）

全称：**Elliptic Curve Diffie‑Hellman Ephemeral，椭圆曲线迪菲‑赫尔曼临时密钥交换**

- E：Elliptic Curve 椭圆曲线，同等安全强度下密钥更短，速度快
- DHE：Diffie‑Hellman Ephemeral，**临时 DH**，每次握手都会生成全新临时公私钥对

> ✨关键特性：**前向安全 (Forward Secrecy)** 即使未来服务器私钥泄露，也无法解密过去的通信记录。因为每一次会话密钥都是临时生成，用完销毁。

> ❗区分 ECDHE vs ECDH

- **ECDHE**：临时，每次握手重新生成密钥对，有前向安全，TLS1.3 全部用这个
- ECDH：静态，服务器固定密钥对，**没有前向安全**，TLS1.3 不再支持

握手流程极简：

1. 客户端生成临时椭圆曲线密钥对，发公钥给服务端
2. 服务端生成临时椭圆曲线密钥对，发公钥 + 证书给客户端
3. 双方用对方公钥 + 自己私钥，本地独立算出**相同的共享密钥**
4. 再通过 HKDF 密钥派生函数，把共享密钥衍生出会话加密密钥，**这个密钥永远不会在网络上传输**

## 2. AEAD：认证加密（干什么：真正加密传输的数据，同时保证机密性 + 完整性 + 防篡改）

全称：**Authenticated Encryption with Associated Data，带关联数据的认证加密**

TLS1.3 **彻底废弃**旧的「加密 + HMAC」分离模式（比如 AES‑CBC + SHA256），全部强制 AEAD 密码套件。

AEAD 一件事同时完成 3 件事：

1. **机密性**：数据加密，窃听者看不懂
2. **完整性**：数据不能被篡改
3. **身份认证**：确认消息没被中间人修改

还有`AD(Associated Data)`关联数据：不加密但是做完整性校验，比如 TLS 报文头，不加密但不能被篡改。

TLS1.3 常用 AEAD 算法：

- `AES‑GCM`：硬件加速，主流首选
- `ChaCha20‑Poly1305`：没有 AES 硬件加速的设备（老安卓、物联网设备）性能更好

> 旧 TLS1.2：AES‑CBC 加密 + SHA256 做校验，分开两步，出现过很多高危漏洞（BEAST、Lucky13）；AEAD 从算法层面规避这类问题。

## 3. AEAD + ECDHE 在 TLS1.3 完整分工

1. **ECDHE 握手阶段**：双方交换临时椭圆公钥，算出共享密钥，HKDF 派生会话密钥（实现前向安全）
2. **AEAD 传输阶段**：用上面得到的会话密钥，对应用层数据做 AEAD 加密输出密文，每一条 TLS 记录自带认证标签 tag；接收方验证 tag，tag 校验失败直接断开连接。

## TLS1.3 密码套件例子

```
TLS_AES_256_GCM_SHA384
TLS_CHACHA20_POLY1305_SHA256
```

> TLS1.3 套件名字**不再写 ECDHE**，因为 TLS1.3 握手固定就是 ECDHE 密钥交换，强制前向安全，不需要写在套件名里。 TLS1.2 套件才会写`ECDHE‑AES‑GCM‑SHA384`。

## 核心优势总结

1. ✅ **前向安全**：ECDHE 临时密钥，私钥泄露也解不开历史流量
2. ✅ **安全更强**：AEAD 算法原生抗篡改，规避大量老式密码漏洞
3. ✅ **速度更快**：椭圆曲线计算开销小，TLS1.3 握手只需要 1‑2RTT
4. ✅ 去掉老旧不安全机制，不再支持静态 ECDH、CBC 模式

### 通俗比喻

- **ECDHE**：两个人公开交换各自的 “密码碎片”，谁都不能直接拿到最终密码，但双方都能本地拼出一把一模一样的钥匙，碎片被别人偷走也拼不出钥匙；每次聊天换全新碎片。
- **AEAD**：拿到这把钥匙之后，给消息上锁，同时贴一个防篡改封条；一旦消息被改动一点点，封条立刻失效。
