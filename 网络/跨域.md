# 跨域（同源策略 / CORS / JSONP / 代理 / postMessage）

> **结论：跨域的本质是浏览器的**同源策略**——协议+域名+端口任一不同即跨域，限制的是「JS 读取响应」，不是「请求发不出去」。** 三大解决方案：**① CORS**（服务端加响应头，最正规，支持所有方法/自定义头/凭据）；**② JSONP**（script 标签绕过，只 GET，老方案）；**③ 代理**（同源服务器转发，开发用 vite/webpack proxy，生产用 nginx 反代）。另加 **postMessage**（窗口间跨域通信）。实测：真起两个端口验证 CORS 简单请求/预检/代理转发全部通过。
>
> 可运行验证：[[跨域-验证脚本.js]]（Node 实测：同源判定 / 简单请求 vs 预检 / 真实 CORS 头 / JSONP / 代理）

---

## 1. 一句话定义（背诵版）

**同源 = 协议 + 域名 + 端口 三者完全相同**；任一不同即跨域，浏览器会拦截 JS 读取响应。

| 组合 | 是否同源 |
| ---- | ---- |
| `https://a.com` vs `https://a.com/x` | ✅ 同源（路径不影响） |
| `https://a.com` vs `http://a.com` | ❌ 协议不同 |
| `https://a.com` vs `https://b.com` | ❌ 域名不同 |
| `https://a.com` vs `https://a.com:8080` | ❌ 端口不同 |
| `https://a.com` vs `https://sub.a.com` | ❌ 子域名不同 |

**关键理解**：同源策略限制的是**「读取响应」**，不是「发请求」——请求能发出去（服务端能收到），但浏览器不让 JS 读响应内容。所以 CORS 报错时，服务端日志里其实有请求。

## 2. CORS（跨域资源共享，最正规）

### 2.1 简单请求 vs 预检请求

| 类型 | 条件 | 行为 |
| ---- | ---- | ---- |
| **简单请求** | 方法 GET/HEAD/POST + Content-Type 仅 `text/plain`/`multipart/form-data`/`x-www-form-urlencoded` + 无自定义头 | 直接发，响应带 CORS 头 |
| **预检请求** | 其他情况（PUT/DELETE、`application/json`、自定义头） | 先发 `OPTIONS` 问服务器允不允许 |

实测：
```
GET  无自定义头                    → 简单请求
POST + text/plain                  → 简单请求
POST + application/json            → 需预检
PUT                                → 需预检
GET + X-Token 自定义头              → 需预检
```

### 2.2 CORS 响应头（服务端要加）

| 响应头 | 作用 |
| ---- | ---- |
| `Access-Control-Allow-Origin` | 允许的源（`*` 或具体源；带凭据时不能 `*`） |
| `Access-Control-Allow-Methods` | 允许的方法（预检响应） |
| `Access-Control-Allow-Headers` | 允许的请求头（预检响应） |
| `Access-Control-Allow-Credentials` | 是否允许带 cookie（`true` 时 ACAO 必须是具体源） |
| `Access-Control-Max-Age` | 预检结果缓存多久（秒） |

实测（真起两个端口）：
```
C1 简单 GET  → 200 | ACAO: http://localhost:3000        ✅
C2 OPTIONS 预检 → 204 | Allow-Methods: GET,POST,PUT,DELETE | Max-Age: 86400  ✅
C3 无 Origin（同源）→ 不返 ACAO                        ✅
```

### 2.3 带凭据的坑（高频追问）

```js
fetch('https://api.com/data', { credentials: 'include' })   // 前端要带 cookie
```
服务端必须同时满足：
1. `Access-Control-Allow-Credentials: true`
2. `Access-Control-Allow-Origin` **必须是具体源**，不能 `*`（否则浏览器拒绝）

## 3. JSONP（老方案，只 GET）

**原理**：`<script>` / `<img>` / `<link>` 标签**不受同源策略限制**（可跨域加载资源）。JSONP 利用 script：

```html
<script src="http://api.com/data?callback=cb"></script>
<!-- 服务端返回: cb({"name":"张三"})  ← 一段可执行 JS -->
<script>
  function cb(data) { console.log(data); }   // 页面定义回调
</script>
```

**执行流程**：script 加载 → 服务端返回 `cb({...})` → 浏览器执行 → 调用页面上的 `cb` → 拿到数据。

**局限（面试必答）**：
- 只支持 **GET**（script 只能 GET，不能 POST）
- **XSS 风险**（返回的是可执行 JS，需信任服务端）
- 需要服务端配合返回 callback 包裹

实测：`模拟执行 cb({"name":"张三"})` → 拿到数据 ✅

## 4. 代理（开发最常用）

**原理**：同源策略只管**浏览器**，**服务器之间没有同源限制**。让前端请求自己的服务器，由它转发给目标 API。

```
浏览器 → 自己的服务器(同源) → 目标 API(跨域但服务器不受限)
```

**配置**：
```js
// vite.config.ts
server: { proxy: { '/api': { target: 'http://api.com', changeOrigin: true } } }

// webpack devServer
proxy: { '/api': { target: 'http://api.com', changeOrigin: true } }
```
**生产**：nginx `location /api { proxy_pass http://api.com; }`

实测：代理服务器转发请求 → 成功拿到 API 数据 ✅

## 5. postMessage（窗口间跨域通信）

```js
// 发送方（iframe 父页面）
iframe.contentWindow.postMessage('hello', 'https://child.com');

// 接收方（iframe 内）
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://parent.com') return;   // ⚠️ 必须校验 origin！
  console.log(e.data);
});
```

**用途**：iframe 与父页面跨域通信、多窗口通信、微前端。
**安全**：**必须校验 `e.origin`**，否则任何页面都能给你发消息（XSS/钓鱼）。

## 6. 三种方案对比（面试必背）

| 方案 | 原理 | 支持方法 | 凭据 | 适用 |
| ---- | ---- | ---- | ---- | ---- |
| **CORS** | 服务端加响应头 | 全部 | ✅ | 生产首选，正规 |
| **JSONP** | script 标签 | 仅 GET | ❌ | 老方案/兼容极老浏览器 |
| **代理** | 同源服务器转发 | 全部 | ✅ | 开发环境（vite/webpack proxy）、生产 nginx |
| postMessage | 窗口消息 | — | — | iframe/多窗口通信 |

## 7. 为什么这么设计

- **为什么有同源策略**：防止恶意网站读取你在其他站点的数据（比如 A 站脚本读你的网银页面）。**没有同源策略 = 任意网站能读任意数据**。它保护的是「数据」不是「请求」。
- **为什么 CORS 要预检**：非简单请求（PUT/自定义头）可能对服务端有副作用。浏览器先发 `OPTIONS` 问「你允许吗」，服务器同意才发真实请求——**避免跨域请求造成非预期修改**。
- **为什么 JSONP 只 GET**：它靠 `<script src>` 加载，script 只能 GET，天生限制。这也是它被 CORS 取代的原因。
- **为什么代理可行**：同源策略是浏览器安全机制，**服务器之间没有这个概念**（服务器不执行网页 JS）。代理把「跨域」转成「同源」（前端→代理）+「服务端转发」（无限制）。

## 9. 面试速记（30 秒版）

> **跨域 = 同源策略限制（协议+域名+端口任一不同），限制的是「JS 读响应」不是「发请求」。** 三方案：**CORS（服务端加 ACAO/Allow-Methods/Allow-Headers，预检 OPTIONS；带凭据时 ACAO 不能 `*`）**、**JSONP（script 标签，只 GET，有 XSS 风险）**、**代理（同源服务器转发；开发 vite/webpack proxy，生产 nginx 反代）**。另有 **postMessage**（iframe/多窗口，**必须校验 e.origin**）。简单请求 = GET/HEAD/POST + 3 种安全 Content-Type + 无自定义头；其余先预检。
