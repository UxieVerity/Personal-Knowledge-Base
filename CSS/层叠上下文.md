# 层叠上下文 + z-index 陷阱

> **结论：z-index 不是「越大越靠前」这么简单——它只在「同一层叠上下文内」比较大小；不同上下文里的 z-index 由父上下文的层叠级别决定（父上下文才是老大）。** 触发层叠上下文的常见属性：`position + z-index`、`transform/opacity < 1/filter/will-change`（这些会创建新上下文）。**面试经典坑：给子元素设超大 z-index 没用，因为它父亲的 z-index 小——「儿子再大也大不过父亲在兄弟里的地位」。**
>
> 可运行验证：[[CSS综合-demo.html]]（浏览器实测：居中 / Grid 自适应列数 / 两栏三栏 / 层叠陷阱 / transform-vs-left 动画 / 响应式断点）

---

## 1. 一句话定义（背诵版）

**层叠上下文（Stacking Context）= 一个独立的「层叠小世界」——内部的 z-index 只在世界里比较；世界之间看世界本身的层叠级别。**

| 概念 | 说明 |
| ---- | ---- |
| **层叠上下文** | 独立的分层小世界，内部元素相对排序 |
| **z-index** | 只影响**同一上下文内**的兄弟元素 |
| **跨上下文** | 不同上下文的元素比较 → **看各自父上下文的层叠级别** |

## 2. 什么会创建层叠上下文（面试必背）

| 触发 | 写法 |
| ---- | ---- |
| **position + z-index** | `position: relative/absolute/fixed` + `z-index` 非 auto |
| **opacity < 1** | `opacity: 0.5` |
| **transform** | `transform: translate(...)`（非 none） |
| **filter** | `filter: blur(...)` 等 |
| **will-change** | `will-change: transform/opacity` |
| **flex/grid 子项 + z-index** | flex 容器内子项 z-index 非 auto 也会 |
| **position + z-index: auto 的定位元素** | `position: relative` + z-index: auto 不创建（默认） |

> **面试关键**：`transform` / `opacity` / `filter` 会**静默创建层叠上下文**——这是「transform 后 z-index 失效」类 bug 的根源。

## 3. z-index 的经典陷阱（实测）

### 陷阱① 儿子再大也大不过父亲

```html
<!-- 期望：B2 盖住 A（因为 B2 z-index: 999 超大） -->
<div class="A" style="z-index: 1">A</div>
<div class="B" style="z-index: 2">
  <div class="B2" style="z-index: 999">B2</div>   <!-- 无效！ -->
</div>
```

**结果**：A 还是盖住 B2。因为 B2 的 z-index:999 只在 B 的上下文内有效；B 的 z-index:2 < A 的 z-index:1...（不，2>1，B 在上，B2 也在上）——**关键是**：如果 B 的 z-index 小于 A，B2 再大也白搭。**比较跨上下文时，看父上下文 B 的 z-index，不看 B2 的 999。**

### 陷阱② transform 静默创建上下文

```html
<!-- A 想被 B 盖住，但 A 有 transform → 创建上下文，内部 z-index 全失效 -->
<div class="A" style="transform: translate(0,0); z-index: auto">
  <div class="A1" style="z-index: 999">盖不住</div>
</div>
<div class="B" style="z-index: 1">B</div>
```

**结果**：B 盖住 A1（A1 的 999 只存在于 A 的上下文内；A 本身 z-index auto，层叠级别低）。

### 陷阱③ 负 z-index 跑到背景

```css
/* z-index: -1 的元素会跑到普通内容的后面（甚至父背景后） */
.box { z-index: -1; }
```

**结果**：负 z-index 元素低于普通流内容 → 常被背景盖住。**用来做「装饰层垫底」**（如给卡片加底部阴影/背景层）。

## 4. 完整层叠顺序（从底到顶，面试背）

```
1. 背景和边框（父元素）
2. 负 z-index 子元素
3. 块级非定位元素（文档流）
4. 浮动元素
5. 行内/行内块元素
6. z-index: 0 / auto 的定位元素
7. 正 z-index 子元素
```

> **一句话**：背景 < 负 z < 块级 < 浮动 < 行内 < z:0 定位 < 正 z。

## 5. 选择器优先级（配套必考）

**优先级 = 三个数**：`(行内样式, id 数, class/属性/伪类数, 元素/伪元素数)`——但面试通常讲「0-0-0-0」四级：

| 选择器 | 优先级（a-b-c） |
| ---- | ---- |
| `!important` | **最高**（但少用） |
| 行内样式 `style=""` | 1-0-0-0 |
| `#id` | 0-1-0-0 |
| `.class` / `[attr]` / `:hover` | 0-0-1-0 |
| `div` / `::before` | 0-0-0-1 |
| `*` / 继承 | 0-0-0-0 |

**同级比较**：从高到低逐级比，谁高谁赢；**完全相等 → 后写的赢**（CSS 层叠）。

**例子**：
```css
#nav .item:hover   /* 0-1-2-0 */
.nav ul li         /* 0-0-1-2 → id 数 0 < 1，前面输 */
```

> **面试坑**：`.class`（0-0-1-0）永远输给 `#id`（0-1-0-0），不管 class 有几个（多个 class 只加第三位）。**ID 权重碾压 class**。

## 6. 为什么这么设计

- **为什么有层叠上下文**：CSS 是「平面叠加」，但页面需要「层次」（弹窗盖内容、下拉盖正文）。层叠上下文把复杂的全局排序**分治**成局部排序——每个上下文内部先排好，再整体参与上层排序。**分治降低复杂度**。
- **为什么 transform/opacity 也创建**：这些属性涉及合成层（GPU 合成），浏览器要为它们建立独立的渲染上下文——顺带获得了层叠上下文属性。这是「性能优化带来的副作用」（了解即可，面试提「合成层」是加分）。
- **为什么 z-index 只在上下文内有效**：如果全局比，改一个深层元素的 z-index 可能影响所有层级 → 不可控。限定在上下文内，改动的影响范围可预测。

## 7. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| z-index 什么时候有效？ | 同一层叠上下文内 + position 非 static（或 flex 子项） |
| 什么创建层叠上下文？ | position+z-index / transform / opacity<1 / filter / will-change |
| transform 会怎样？ | 静默创建上下文 → 内部 z-index 失效（经典 bug） |
| 跨上下文 z-index 怎么比？ | 看父上下文的层叠级别，不看子元素的 |
| 负 z-index 有什么效果？ | 跑到内容后面（背景层/垫底装饰） |
| 优先级怎么算？ | 行内 > id > class/属性 > 元素；同级后写赢 |
| class 能打赢 id 吗？ | 不能，ID 权重碾压（多 class 只加第三位） |

## 8. 面试速记（30 秒版）

> **z-index 只在同一层叠上下文内有效。** 触发上下文：`position+z-index`、`transform`、`opacity<1`、`filter`、`will-change`。**经典坑：子元素 z-index 999 盖不住父兄弟——跨上下文看父的 z-index（儿子再大不过父亲）。transform 会静默建上下文 → 内部 z-index 失效。** 层叠顺序：背景 < 负 z < 块级 < 浮动 < 行内 < z:0 < 正 z。**优先级**：行内 > `#id` > `.class/属性` > `元素`，同级后写赢；ID 碾压 class。层叠上下文 = 分治排序（局部先排再整体排）。
