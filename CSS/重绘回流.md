# 重绘与回流（Reflow & Repaint）

> **结论：回流（Reflow）= 布局变化触发浏览器重新计算几何（位置/尺寸），重绘（Repaint）= 只改外观（颜色/阴影）不触发布局。回流一定伴随重绘，重绘不一定回流。** **性能关键：回流代价远高于重绘**——它要重新走「布局 → 绘制 → 合成」整条管线。**优化核心：少触发回流，读改分离（避免强制同步布局），用 transform/opacity 做动画（只走合成）。**
>
> 可运行验证：[[CSS综合-demo.html]]（浏览器实测：居中 / Grid 自适应列数 / 两栏三栏 / 层叠陷阱 / transform-vs-left 动画 / 响应式断点）

---

## 1. 一句话定义（背诵版）

| | 回流 Reflow | 重绘 Repaint |
| ---- | ---- | ---- |
| 触发 | 几何变化（尺寸/位置/增删节点） | 外观变化（颜色/背景/阴影/visibility） |
| 代价 | **高**（重算布局，重走管线） | 低（跳过布局，直接绘制） |
| 关系 | 必然伴随重绘 | 不一定触发回流 |

**完整管线**：`JS → 样式 → 布局(Layout/Reflow) → 绘制(Paint/Repaint) → 合成(Composite)`。**回流 = 重走 Layout 及之后；重绘 = 只走 Paint 及之后；transform/opacity 只走 Composite**（最快）。

## 2. 什么触发回流（面试必背清单）

| 类别 | 具体操作 |
| ---- | ---- |
| **几何变更** | 改 width/height/margin/padding/border/top/left |
| **节点增删** | `appendChild` / `removeChild` / 隐藏显示 |
| **内容变化** | 改文本、`display:none` → block |
| **窗口缩放** | resize |
| **读取几何** | **`getBoundingClientRect` / `offsetWidth` / `clientHeight` / `scrollTop`**（如果布局是脏的，读会强制回流） |

## 3. 强制同步布局（Forced Synchronous Layout，核心坑）

```js
// ❌ 读改交替 → 每次读都强制回流（布局刚被改脏，一读就重排）
for (let i = 0; i < 100; i++) {
  box.style.width = i + 'px';      // 改（布局变脏）
  console.log(box.offsetWidth);    // 读 → 强制同步回流！
}

// ✅ 先读后改（批量化）：读时布局还干净（不强制），改完最后统一回流
const widths = [];
for (let i = 0; i < 100; i++) widths.push(box.offsetWidth);  // 全读（干净）
for (let i = 0; i < 100; i++) box.style.width = i + 'px';    // 全改（最后一次回流）
```

**原理**：浏览器是「懒布局」——样式改了不立即重排，攒到「需要时」统一做。但**读几何时**如果有待处理的样式变更，必须**立即重排**才能给出准确值 → 强制回流。**读写交替 = 每次读都触发一次回流**（100 次！）；**先读后改 = 只回流 1 次**。

> **面试话术**：「浏览器批量处理样式变更，但读几何会打断批量。读改分离——先统一读、再统一改——避免每次读都强制回流。」

## 4. 优化手段（面试背）

| 手段 | 说明 |
| ---- | ---- |
| **读改分离** | 先读后改，避免强制同步布局 |
| **批量 DOM 操作** | 用 `DocumentFragment` 或先拼字符串一次性插入 |
| **避免逐条改样式** | 用 `class` 切换代替逐条 `style.x = ` |
| **transform/opacity 做动画** | 只走合成层，**不触发回流重绘**（GPU） |
| **`will-change: transform`** | 提前告诉浏览器「要动画了」→ 建独立层 |
| **防抖/节流 + 移除监听** | 减少高频触发（scroll/resize） |
| **脱离文档流动画** | 动画元素 `position: absolute`，减少影响范围 |

**为什么 transform 快**：transform 只改变元素的**合成属性**（GPU 层位移/缩放），不改变文档流几何 → 浏览器跳过 Layout 和 Paint，直接 Composite。opacity 同理。**这就是「能用 transform 不用 left/top」的原因**。

## 5. 重绘触发（相对少）

- 颜色：`color` / `background-color` / `border-color`
- 阴影：`box-shadow` / `text-shadow`
- 其他：`visibility` / `outline`
- 这些只改变外观，几何不变 → 只重绘，不回流

## 6. 为什么这么设计

- **为什么回流代价高**：布局计算依赖整棵 DOM 树——一个元素尺寸变，它的后代、兄弟、甚至祖先的布局都可能要重算（取决于是否脱离文档流）。这是全局性的计算，不是局部重画。绘制（重绘）只处理「像素画哪」，「怎么排」已经算好了。
- **为什么浏览器懒布局**：如果每次改样式立即重排，一次 `el.style.width='x'; el.style.height='y'` 就要重排两次。懒布局把多次改动**合并成一次重排**——「改完再算」比「改了就算」高效得多。代价就是「读几何会打断懒布局」（强制同步）。
- **为什么有合成层**：把频繁动画的元素提升到独立 GPU 层，动画只在该层做位移/透明，不影响其他层的布局和绘制。这是「用空间（显存）换时间（性能）」。

## 7. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 回流和重绘区别？ | 回流=几何重算（重走布局）；重绘=外观重画；回流必然伴随重绘 |
| 什么触发回流？ | 尺寸/位置/增删节点/内容变化/resize/读几何 |
| 强制同步布局？ | 布局脏时读几何 → 强制重排；读写交替 = 每次读都回流 |
| 怎么避免？ | 读改分离、批量 DOM、class 切换、transform 动画 |
| 为什么 transform 快？ | 只走合成层（GPU），跳过布局和绘制 |
| 动画用 left 还是 transform？ | transform（left 触发回流） |
| 重绘触发什么？ | 颜色/阴影/visibility（外观不变几何） |

## 8. 面试速记（30 秒版）

> **回流（几何重算，重走布局）> 重绘（外观重画）；回流必带重绘，重绘不一定回流。** 触发回流：尺寸/位置/增删节点/内容/读几何。**核心坑：强制同步布局——读改交替，每次读都回流；先读后改只回流一次。** 优化：**读改分离、批量 DOM、class 切换、transform/opacity 动画（只走合成层 GPU）、will-change、脱离文档流动画、防抖节流。** 一句话：「能用 transform 绝不用 left/top」。
