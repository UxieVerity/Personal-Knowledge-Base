# 微任务时序深度（Promise 视角）

> **结论：微任务队列「每轮必清空」——一个宏任务执行完，会一口气把当前所有微任务（包括微任务里新加的）排空，才取下一个宏任务。** Promise.then / async 续体 / queueMicrotask 都在**同一微任务队列**，严格 FIFO。Node 的 `process.nextTick` 是「当前宏任务尾部」的独立优先队列，**先于** Promise 微任务。关键推论：**微任务太多会阻塞渲染/掉帧**。
>
> 可运行验证：[[微任务时序-验证脚本.js]]（Node 实测：宏任务间排空 / 微任务嵌套同批 / FIFO / 多 then / 不被打断 / nextTick 优先级）

---

## 1. 五个经典时序论断（实测）

### ① 宏任务之间排空所有微任务（实测 A）

```
[A] 顺序 = ["同步","脚本级微任务","宏任务1","宏任务1的微任务","宏任务2"]
```

**关键**：宏任务1 执行中加的微任务（`宏任务1的微任务`），在**宏任务2 之前**执行——微任务队列在每个宏任务后必清空。

### ② 微任务嵌套微任务：同批排空，不插队宏任务（实测 B）

```
[B] 顺序 = ["同步","微任务1","微任务1后","微任务1产生的微任务","宏任务"]
```

**关键**：微任务1 里又加了一个微任务，它**仍在同一批**排空（在宏任务之前）。微任务队列是「清空到空为止」，不是「清空当前快照」。

### ③ Promise.then 与 async 续体同队列 FIFO（实测 C）

```
[C] 顺序 = ["同步","then续体","async续体"]
```

**关键**：`await undefined` 的续体和 `Promise.resolve().then` 进**同一个微任务队列**，按注册顺序执行。**async/await 就是 Promise 的语法糖**（见 [[async-await本质]]）。

### ④ 多个 then 按注册顺序排队（实测 D）

```
[D] 顺序 = ["同步","第1个then:值","第2个then:值","第3个then:值"]
```

**关键**：同一个 Promise 上注册多个 then，**全部执行**（不是只执行第一个），按注册顺序。这就是手写 Promise 里 `handlers` 数组的意义（见 [[手写题/Promise基础版]]）。

### ⑤ 微任务连续执行，不被宏任务打断（实测 E）

```
[E] 顺序 = ["同步","微0","微1","微2","宏任务"]
```

**关键**：即使宏任务已经排队，微任务也**一口气跑完**才轮到你。这是「微任务优先级 > 宏任务」的体现。

### ⑥ Node 特有：nextTick 先于 Promise（实测 F）

```
[F] 顺序 = ["同步","nextTick","Promise微任务"]
```

**关键**：`process.nextTick` 不是标准微任务队列，是「当前操作尾部」的独立优先队列——**先于** Promise 微任务。浏览器没有 nextTick。

## 2. 完整时序模型（背诵）

```
同步代码
  ↓
微任务队列（Promise.then / async 续体 / queueMicrotask / MutationObserver）—— 清空到空
  ↓
下一个宏任务（setTimeout / I/O / 事件）
  ↓
（循环）
```

**浏览器**：微任务清空后 → Update Rendering（渲染）→ 空闲回调（rIC）→ 下一个宏任务（详见 [[浏览器事件循环(EventLoop)]]）。

**Node 额外**：每个宏任务尾部，`process.nextTick` 队列先于 Promise 微任务。

## 3. 为什么这么设计（面试加分）

- **为什么微任务必清空**：保证 Promise 链的原子性——`.then().then().then()` 中间不能插入别的任务（否则链会乱）。微任务队列「清到空」让依赖关系在同批完成。
- **为什么微任务优先级 > 宏任务**：Promise 是「当前任务的结果延续」，应在当前任务收尾时尽快完成，而不是排队等下一个宏任务（那会明显变慢）。
- **为什么微任务会阻塞渲染**：渲染在微任务清空**之后**。如果微任务无限循环添加自己，微任务队列永远清不空 → 渲染永远到不了 → **页面卡死/掉帧**。这是面试经典题「微任务能不能阻塞渲染」。

## 4. 高频追问速答

| 问题 | 一句话答案 |
| ---- | ---- |
| 微任务每轮必清空吗？ | 是——清空到空才取下一个宏任务 |
| 微任务里加微任务？ | 同批继续清（不插队宏任务），队列清到空为止 |
| then 和 async 谁先？ | 同队列 FIFO，按注册顺序（都是微任务） |
| 多个 then 都执行吗？ | 都执行，按注册顺序（handlers 数组） |
| 微任务会被宏任务打断吗？ | 不会，一口气跑完 |
| nextTick 和 Promise 谁先？ | Node 里 nextTick 先（独立优先队列）；浏览器无 nextTick |
| 微任务会阻塞渲染吗？ | 会——渲染在微任务清空后，无限微任务导致永远不渲染 |

## 5. 面试速记（30 秒版）

> **微任务每轮清空到空，才取下一个宏任务。** 五个要点：**① 宏任务里加的微任务，在下一个宏任务前执行；② 微任务嵌套微任务同批排空（清到空，不插队宏任务）；③ then/async 续体/queueMicrotask 同队列 FIFO；④ 多 then 按注册顺序全执行；⑤ 微任务一口气跑完不被宏任务打断。** Node 的 `nextTick` 是「当前宏任务尾部」独立优先队列，先于 Promise 微任务。**面试点**：微任务太多会阻塞渲染（渲染在微任务清空之后）。
