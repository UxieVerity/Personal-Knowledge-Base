# JS 异常与调用栈 · 面试速记

> 高频追问「死循环 vs 递归超栈」：一个伤栈、一个伤 CPU，机理完全不同。30 秒能讲完，实测数据见下方表格。

---

## 1. 一句话对比（背诵版）

> **递归超栈是 `RangeError`**：每层调用压一帧，栈长高到 V8 上限（本机实测 ~12500 帧）就抛异常——**可捕获、栈回退、程序继续跑**。**死循环是栈不增长**（始终 1 层），**永远不会触发栈错误**——只是主线程被占死、事件循环阻塞、页面无响应、Node 不退出，**没有任何异常能接**。一个伤栈，一个伤 CPU。

## 2. 核心机制

| | 递归超栈 | 死循环 |
| ---- | ---- | ---- |
| 报错类型 | `RangeError: Maximum call stack size exceeded` | **无报错**，纯挂起 |
| 调用栈 | 每帧压栈，长高到上限 | 始终 1 层，不增长 |
| 触发条件 | 递归深度超过 V8 栈上限（~1 万+ 帧，默认栈约 1MB） | 循环条件永远为真 |
| 能否捕获 | `try/catch` 可接住，栈回退，程序存活 | 无法捕获——没有异常可接 |
| 事件循环 | 报错后恢复运行 | 被彻底阻塞，timer/IO 全排队 |
| 资源占用 | 栈内存溢出（瞬时） | CPU 打满，内存不涨 |

## 3. 实测数据（本机 Node）

```
=== 递归超栈 ===
报错类型: RangeError
错误信息: Maximum call stack size exceeded
触发深度约: 12508

=== 死循环 ===
同步死循环 200 ms 循环约 400 万次，期间无任何报错

=== 死循环阻塞事件循环 ===
setTimeout(100ms) 在 300ms 死循环结束后才执行
```

**要点**：死循环 200ms 跑 400 万次迭代，栈始终 1 层——证明它不是「栈溢出」，是「时间黑洞」。

## 4. 高频追问速答

- **死循环会报栈溢出吗？** 不会。栈不增长，永远触发不了栈上限
- **为什么引擎不拦死循环？** 停机问题——引擎无法证明循环是否永不终止，只能把主线程一直交给你
- **死循环怎么结束？** 浏览器「页面无响应」提示让用户手动杀；Node 进程只能外部 kill
- **递归都能改迭代吗？** 是，改循环/尾调用优化（V8 有 TCO 语义但未默认开启），栈溢出本质是深度超过硬件限制
- **栈上限多大？** V8 默认约 1MB / ~1 万+ 帧（实测 12508），`--stack_size` 可调

> 30 秒完整版：**递归超栈 = RangeError**，每层压帧长高到上限（~1.2 万帧）就抛，`try/catch` 能接住、栈回退、程序继续。**死循环 = 栈不增长**（始终 1 层），所以永远不触发栈错误，只是占死主线程阻塞事件循环，页面无响应、Node 不退出。**一个伤栈、一个伤 CPU**，区别在「结构错误可捕获」vs「逻辑错误无法证明终止」。
