# 网络链路 · 面试速记

> **速记定位**：面试被问到「输入 URL 后发生了什么 / HTTP 网络栈 / 为什么页面加载慢」时，30 秒内把整条网络链路讲清。详细原理见文末对应笔记。

---

## 1. 一条主线：URL → 页面渲染，网络部分做什么

```
① 缓存/重定向(发请求前)  →  ② DNS 解析  →  ③ TCP 三次握手  →  ④ TLS 握手（HTTPS）  →  ⑤ HTTP 请求/响应  →  ⑥ 断开连接
（命中=0请求 / 3xx跟随）   （查 IP）      （建立连接）          （加密协商）              （取资源）          （FIN/RST）
```

**30 秒主线速记**（对应「从输入网址到页面展示」的网络段）：

| 环节 | 一句话 | 详细 |
| --- | --- | --- |
| 缓存/重定向 | 缓存命中=0 请求；no-cache→304 省响应体；3xx 自动跟随 Location | [[从浏览器输入网址到页面完整展示全过程]]（§3） |
| DNS 解析 | 域名 → IP，走 **UDP 53**，本地命中 ~0.03ms | [[从浏览器输入网址到页面完整展示全过程]]（§2/§4） |
| TCP 三次握手 | 确认双方收发能力 + 协商 ISN，**1 RTT** | [[TCP 三次握手（建立连接）+ 四次挥手（断开连接）]] |
| TLS 握手 | HTTPS 加密协商：**TLS1.2 需 2-RTT，TLS1.3 只要 1-RTT** | [[TLS12和TLS13的区别]] |
| HTTP 请求 | 版本决定并发模型：H1 串行 / H2 多路复用 / H3 独立流 | [[HTTP1和HTTP2、HTTP3 的区别]] |
| 断开连接 | FIN 优雅关闭（四次挥手） / RST 异常断开 | [[TCP FIN 和 RST：正常关闭 vs 异常断开]] |

## 1.5 缓存与重定向速记（发请求前，面试高频）

| 概念 | 一句话 | 详细 |
| --- | --- | --- |
| 缓存查找顺序 | Service Worker → 内存 → 磁盘 → 网络；**命中=0 网络请求** | [[从浏览器输入网址到页面完整展示全过程]]（§3） |
| 强缓存 | `Cache-Control: max-age` 新鲜期内直接用，不发请求 | §3.2 |
| 协商缓存 | 过期带 `ETag/If-None-Match`、`Last-Modified/If-Modified-Since` 校验 → **304** | §3.2 |
| no-cache vs no-store | **no-cache=存副本但每次校验（≠不缓存）**；no-store=永不存 | §3.2 |
| 301 vs 308 / 302 vs 307 | **区别=方法保留**：308/307 保留 POST 请求体，301/302 可能丢 | §3.1 |
| 304 vs 重定向 | 304 不是重定向：无 Location，是「校验通过复用本地」 | §3.1 |

## 2. 连接建立要花几次往返（面试高频）

| 版本 | TCP 握手 | TLS 握手 | 合计（首访） | 再次访问 |
| --- | --- | --- | --- | --- |
| HTTP/1.1 | 1 RTT | TLS1.2：2 RTT | **3 RTT** | Session 复用略少 |
| HTTP/2 | 1 RTT | TLS1.3：1 RTT | **2 RTT** | 0-RTT |
| HTTP/3 (QUIC) | 0（UDP 无握手） | 内置 QUIC 握手 | **1 RTT** | **0-RTT** |

> **一句话**：H1 首访 3 RTT → H3 只要 1 RTT（重连 0-RTT），省掉的就是「TCP 握手 + TLS 握手」逐步内合的过程。

## 3. 三次握手 vs 四次挥手（高频对比）

| | 三次握手 | 四次挥手 |
| --- | --- | --- |
| 方向 | 建立连接（Client 主动） | 断开连接（全双工各自关） |
| 报文 | SYN → SYN+ACK → ACK | FIN → ACK → FIN → ACK |
| 为什么 N 次 | 服务端 SYN+ACK 能**合并**成一个报文 | 收到 FIN 后的 ACK 与业务发完才发的 FIN **不能合并**（中间可能要传数据） |

## 4. FIN vs RST 一句话

> **FIN = 礼貌「我说完了，再见」；RST = 直接挂断电话「不谈了」。**

| | FIN | RST |
| --- | --- | --- |
| 场景 | 正常 close() | 进程崩溃/端口不存在/连接已失效 |
| 善后 | 有序，缓冲区数据尽量发完 | 直接丢弃所有未发送/未接收数据 |
| 挥手 | 走完整四次挥手 | 无，直接断开 |

## 5. 页面加载慢 → 网络侧排查（速查）

| 现象 | 可能原因 | 手段 |
| --- | --- | --- |
| 首访慢 | 3 RTT 握手（H1+TLS1.2） | 升级 H2/TLS1.3/H3 |
| 资源排队 | H1 队头阻塞 | 升级 HTTP/2 多路复用 |
| 弱网丢包卡 | H2 共享连接 TCP 层 HOL | 升级 HTTP/3 (QUIC) |
| 重复访问慢 | 每次都完整握手 | 0-RTT / keep-alive 复用 |
| 连接堆积 | 服务端卡 CLOSE_WAIT | 代码忘了 close()（见 [[TCP FIN 和 RST：正常关闭 vs 异常断开]]） |
