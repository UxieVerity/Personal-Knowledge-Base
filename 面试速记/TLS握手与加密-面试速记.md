# TLS 握手与加密 · 面试速记

> **速记定位**：面试被问到「HTTPS 为什么安全 / TLS1.2 和 1.3 的区别 / 什么是 ECDHE、AEAD / 前向保密」时，30 秒答完。详细见 [[TLS12和TLS13的区别]]、[[TLS1.3 AEAD + ECDHE]]。

---

## 1. TLS 解决什么问题

> HTTPS = HTTP over TLS。TLS 提供四件事：**加密**（防窃听）、**完整性**（防篡改）、**身份认证**（防中间人）、**前向保密**（防历史流量被将来破解）。

## 2. TLS 1.2 vs 1.3（速记表）

| 维度 | TLS 1.2 | TLS 1.3 |
| --- | --- | --- |
| 握手往返 | **2-RTT** | **1-RTT** |
| 会话恢复 | Session ID / Ticket | **PSK + 0-RTT**（首包即数据） |
| 密码套件 | 几十个，含老弱（RSA、CBC） | **砍到 5 个**，全用 AEAD + ECDHE |
| 密钥交换 | RSA（无前向保密）/ ECDHE | **仅 ECDHE**（强制前向保密） |
| 签名算法 | SHA-1 也能用 | 淘汰 SHA-1，最低 SHA-256 |

## 3. 实测数据（背数字用）

> 本机 Node 对真实站点分别强制 TLS1.2 / TLS1.3 握手、各 5 次取平均。机器/网络不同数值有差异，**TLS1.3 更快这一方向稳定**。

| 站点 | TLS1.2 | TLS1.3 | 差值 |
| --- | --- | --- | --- |
| bilibili.com | 79.2ms | 56.9ms | **22.4ms** |
| douyin.com | 106.9ms | 67.3ms | **39.5ms** |
| taobao.com | 107.3ms | 77.3ms | **30.1ms** |

> **关键读数**：TLS1.3 平均快 **22~40ms ≈ 一个 RTT**——正对应「2-RTT → 1-RTT」省掉的那次往返。注意百度/QQ 只开 TLS1.2（强制 TLS1.3 报 `ERR_SSL_TLSV1_ALERT_PROTOCOL_VERSION`），说明现实世界 TLS1.3 尚未全量部署。

## 4. 为什么握手从 2-RTT 变 1-RTT

- **TLS1.2**（无恢复）：ClientHello → ServerHello+证书+ServerKeyExchange → 客户端算密钥+Finished → 服务器 Finished = **2 次往返**才发数据
- **TLS1.3**：客户端在 ClientHello 里就带上 **key_share**（预测的 ECDHE 参数），服务器一个 ServerHello+Finished 就能回 → **1 次往返**即出数据
- 取舍：TLS1.3 要求客户端**提前猜**密钥交换算法（猜错多一次 HelloRetryRequest 兜底，概率低）

## 5. 为什么砍密码套件

> TLS1.2 的 RSA 密钥交换**没有前向保密**（私钥泄露 → 历史流量全被解密），CBC 有 padding oracle 攻击（BEAST/POODLE）。TLS1.3 砍到 5 个套件、全用 AEAD + ECDHE：安全集收敛，配置错误面变小。**取舍：放弃老设备兼容，换安全确定性。**

## 6. ECDHE 与 AEAD 一句话

> **ECDHE 负责安全协商出会话密钥，AEAD 负责加密 + 完整性校验，TLS1.3 强制只用这套组合。**

| 组件 | 干什么 | 关键点 |
| --- | --- | --- |
| **ECDHE** | 双方在不安全网络协商共同会话密钥 | **临时**密钥对，每次握手全新 → **前向安全**（私钥泄露也解不开历史流量） |
| **AEAD** | 加密 + 完整性 + 防篡改，一件事同时完成 | AES-GCM（硬件加速）/ ChaCha20-Poly1305（无 AES 硬件设备） |

- 前向安全原理：会话密钥每次临时生成、用完销毁，服务器私钥泄露也无法解密过去的通信记录
- ECDH（静态）没有前向安全，TLS1.3 不再支持；套件名不再写 ECDHE 因为 TLS1.3 握手固定就是它

## 7. 0-RTT 是双刃剑（面试追问）

> 0-RTT 让上次握手过的客户端**首包就能带数据**（PSK 恢复），性能最好。但 **0-RTT 数据无法防重放**（中间人可重放第一条请求）→ 只适用于幂等请求（GET），不能用于 POST 下单。

## 8. 与 HTTP 版本联动（加分点）

- **HTTP/2** 要求底层 TLS1.2+（ALPN 协商）→ TLS1.3 让 H2 的「TCP+TLS」两步握手也变快
- **HTTP/3 (QUIC)** 直接把 TLS1.3 内置进 QUIC 握手（0-RTT/1-RTT 合一），不再有独立 TLS 层——这是 H3「连接建立更快」的另一半原因
