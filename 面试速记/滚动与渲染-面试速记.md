# 滚动与渲染 · 面试速记

> **速记定位**：面试被问到"滚动 / 渲染 / passive / 强制同步布局 / 弹窗锁滚动"时，30 秒内答完。详细原理见文末对应笔记。

---

## 1. Update Rendering 阶段的事件顺序

```
resize 事件(Step 8) → scroll 事件(Step 9) → CSS动画(Step 11) →
rAF 回调(Step 14) → 样式+布局 → ResizeObserver 递送(Step 16) →
IntersectionObserver 计算(Step 19) → Paint(Step 22)
```

**速记口诀**：`resize/scroll → 动画 → rAF → 布局 → RO → IO → Paint`

- ✅ rAF 在 RO 之前（Step 14 < 16）
- ✅ scroll/resize 事件在 rAF **之前**（Step 8/9 < 14）
- ✅ 实测验证：每帧稳定 `scroll → rAF → RO`

## 2. scroll 是"滚动后"，wheel/touchmove 是"滚动前"

| 事件 | 时机 | 偏移已应用？ | cancelable | preventDefault | passive |
| --- | --- | --- | --- | --- | --- |
| `wheel` / `touchmove` | 滚动**前** | ❌ 未变 | ✅ true | ✅ 可取消滚动 | ✅ 有效 |
| `scroll` | 滚动**后** | ✅ 已应用 | ❌ false | ❌ 无效 | ❌ 无效 |

- **scroll**：滚动已经发生了的通知 → 不可取消 → 加 passive 也拦不住
- **wheel/touchmove**：将要滚动的驱动事件 → 可取消 → passive:false 时 preventDefault 能阻止滚动

## 3. passive 一句话

> **passive:true = 承诺不 preventDefault → 浏览器不等 JS 就能提前滚动。**

- 只对"滚动前、可取消"的事件（touchmove/touchstart/wheel）有效
- **scroll 加了也无效**（不可取消，浏览器本来就不用等它）
- 现代浏览器：document 级 touchstart/touchmove 默认 passive（Chrome 56+），wheel 默认 passive（Chrome 73+）
- 需要 preventDefault 时**必须显式 `passive:false`**

## 4. 强制同步布局（Forced Synchronous Layout）

> **触发条件 = 布局脏 + 读几何。** 与读哪个属性无关，与 scroll 无关，只与"之前有没有写"有关。

```
改几何样式（margin/width/top...）→ 布局被弄脏
  ↓
读几何属性（offsetWidth/gBCR/getComputedStyle().width）
  ↓
浏览器无法回答 → 强制同步重排
```

**速记要点：**
- 布局是**页面级**的：改任何元素的几何，读任何元素都会重排
- 只有"失效后第一次读"重排，之后连续读命中缓存
- `el.style.width` 读的是字符串，**不重排**
- 最坏形态 **Layout Thrashing**：读写交替，每帧几十次重排
- 优化：rAF 批处理 / 读写分离 / 用 transform（不脏布局）

## 5. dialog 锁滚动（弹窗阻止背景滚动）

| 方案 | 一句话 | 适用 |
| --- | --- | --- |
| `<dialog>.showModal()` | 浏览器原生 modal 锁 | 现代浏览器、简单弹窗 |
| `body { overflow:hidden; position:fixed }` | 桌面最可靠，记录/还原 scrollY | 桌面 PC |
| `overscroll-behavior: contain` | 纯 CSS 切断滚动链 | 弹窗内独立滚动列表 |
| `touchmove` preventDefault + `passive:false` | 移动端最可靠，白名单放行 | 移动端 H5 |

**一句话**：桌面 overflow:hidden，移动端 touchmove preventDefault（必须 passive:false），弹窗内独立滚动用 overscroll-behavior:contain，简单场景直接 `<dialog>.showModal()`。
