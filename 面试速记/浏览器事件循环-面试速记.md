# 浏览器事件循环 · 面试速记

> 事件循环是浏览器原理面试的**必问题**。本速记覆盖最常被问的核心点，详细见 [[浏览器事件循环(EventLoop)]]。

---

## 1. 一轮事件循环的顺序

```
① 取出一个宏任务执行 → ② 清空微任务队列 → ③ 判断是否更新渲染 → ④ 渲染 → ⑤ 空闲回调
```

| 机制 | 执行保证 | 队列 | 可被跳过 |
| --- | --- | --- | --- |
| 宏任务（setTimeout 等） | 队列非空即取 | Task Queue | ❌ |
| 微任务（Promise.then 等） | 每轮必清空 | Microtask Queue | ❌ |
| Update Rendering | 无保证 | 浏览器内部调度 | ✅ 可跳过 |
| requestIdleCallback | 无保证 | Idle Callback List | ✅ 可跳过 |

## 2. 微任务 vs 宏任务 vs 渲染

```
[宏任务] → [微任务(必清空)] → [渲染(可跳过)] → [空闲回调] → [下一个宏任务]
```

**速记要点：**
- 微任务在**当前宏任务结束后、渲染前**统一清空
- 微任务里再追加微任务 → 继续清空（直到队列空）
- rAF 挂在**渲染阶段内**（step 14），比 setTimeout 更贴近屏幕刷新
- `requestIdleCallback` 是第三类，**不保证执行**，有空才做

## 3. 三大 Observer 的区别

| Observer | 执行位置 | 规范用语 |
| --- | --- | --- |
| MutationObserver | 微任务（渲染前） | queue a microtask |
| ResizeObserver | 渲染阶段内（rAF 后、布局后） | run resize observation steps |
| IntersectionObserver | **计算**在渲染阶段，**回调**异步派发 | queue a task |

## 4. 高频追问点

- **setTimeout(fn, 0) vs rAF 动画**：rAF 跟屏幕刷新同步、不积压；setTimeout 可能掉帧
- **为什么微任务里 Promise 比 setTimeout 先**：微任务清空在宏任务之间，setTimeout 是下一个宏任务
- **渲染可被跳过**：页面隐藏 / 无可见变化 / 无 rAF 注册时整轮跳过
