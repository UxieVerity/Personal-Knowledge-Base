# 原型与原型链、继承

> **结论：JavaScript 没有"类"，只有对象，对象之间通过「原型链」共享属性与行为。** 三个核心概念：**`prototype`**（只有函数有，`new` 时作为实例的原型）、**`__proto__`**（每个对象都有，指向构造函数的 `prototype`，构成链）、**`constructor`**（`prototype` 上的属性，指回构造函数）。访问属性时**沿 `__proto__` 链向上查找**（自身 → 原型 → 原型的原型 → … → `null`），找不到返回 `undefined`。**继承的本质**就是"把子类的 `prototype` 连到父类原型链上"——ES5 各继承方式（原型链/构造/组合/寄生组合）都是在调这个链条的接法，`class extends` 是 ES6 语法糖，底层仍是原型链。
>
> 可运行验证：[[原型链-验证脚本.js]]（Node 实测三角关系/原型链路径/属性遮蔽/instanceof）、[[继承方式-验证脚本.js]]（Node 实测 5 种继承的坑）、[[原型链可视化-demo.html]]（可交互：选对象看它的 `__proto__` 链）

## 1. 背景：JS 为什么用原型而不是类

| 维度 | 传统类（Java/C++） | JS 原型（1995 诞生起） |
| ---- | ------------------ | ---------------------- |
| 核心概念 | 类（class）是模板，实例从类创建 | **只有对象**，对象直接继承对象 |
| 复用方式 | 类继承（extends） | **原型链**（`__proto__` 串联） |
| 创建实例 | `new 类()` | `new 构造函数()` 或 `Object.create()` |
| 动态性 | 类定义后难改 | **运行时随时可以改原型**（`prototype.xxx = ...` 立刻影响所有实例） |

- JS 诞生时（1995，Brendan Eich 用 10 天设计）**刻意不用 class**，因为当时流行"self 语言"的原型式继承——`new` 只是让"构造函数 + 原型"看起来像类的语法糖。
- 结果：**JS 的对象模型极其动态灵活**（可随时给原型加方法、`Object.create` 任意指定原型），但代价是**原型链查找比静态类慢**、概念上容易绕（`prototype`/`__proto__` 两个词太像）。

## 2. 核心机制：prototype / `__proto__` / constructor 三角关系

### 2.1 一张图看懂

```
                          ┌─────────────────────────────┐
                          │       Person.prototype      │
                          │  constructor ──→ Person      │
                          │  sayHi: ƒ                   │
                          └──────────┬──────────────────┘
                                     │ __proto__ (指向 Object.prototype)
┌──────────────┐    __proto__    ┌──────────────┐    __proto__    ┌──────────────────┐    __proto__
│  p (实例)     │ ──────────────► │ Person.prototype│ ─────────────► │  Object.prototype │ ────────────► null
│  name: 张三   │                 │              │                  │  toString: ƒ     │
└──────────────┘                 └──────────────┘                  └──────────────────┘

Person 函数本身: Person.__proto__ ──► Function.prototype ──► Object.prototype ──► null
```

### 2.2 实测：三角关系的 5 个关键等式

```
[1] p.__proto__ === Person.prototype ?          true
[2] Person.prototype.constructor === Person ?   true
[3] p.constructor === Person ?                  true   ← 实例没有 constructor，沿链找到原型上的
[4] Person.prototype.__proto__ === Object.prototype ? true
[5] Object.prototype.__proto__ === null ?       true   ← 链的终点
```

| 等式 | 含义 |
| ---- | ---- |
| `p.__proto__ === Person.prototype` | 实例的 `__proto__` 指向**构造函数的 prototype**（`new` 时建立的连接） |
| `Person.prototype.constructor === Person` | 原型上的 `constructor` 指回构造函数（默认值，可被改） |
| `p.constructor === Person` | 实例没有 `constructor`，**沿原型链**找到 `Person.prototype.constructor` |
| `Person.prototype.__proto__ === Object.prototype` | 所有对象的原型链最终汇合到 `Object.prototype` |
| `Object.prototype.__proto__ === null` | 链的终点是 `null`（不是 `undefined`，也不是无限循环） |

### 2.3 原型链查找（属性访问的规则）

```
[8] 对象上没有 sayHi 时，沿原型链找到: Hi, I am 张三
[9] p.hasOwnProperty("name") ? true | hasOwnProperty("sayHi") ? false (sayHi 在原型上)
```

- 访问 `p.sayHi`：先找 `p` 自身 → 没有 → 找 `p.__proto__`（Person.prototype）→ 找到 `sayHi`。
- `p.name` 是**自身属性**（`hasOwnProperty` true）；`sayHi` 是**继承属性**（自身 false，原型上 true）。
- 查找直到 `null`：**链上任何一层都没有 → `undefined`**。
- **属性遮蔽（shadowing）**：给 `p2` 自身赋同名属性，就**遮蔽**原型上的方法（实测 `p2.sayHi()` 用自己的，`p.sayHi()` 不受影响）。

```
[16] p2 自身有 sayHi 属性 ? true
[17] p2.sayHi() = 我自己定义的 sayHi | p.sayHi() = Hi, I am 张三 (p2 遮蔽了原型方法，p 没被影响)
```

### 2.4 函数也是对象：两条链

```
[14] Person.__proto__ === Function.prototype ? true
[15] Function.prototype.__proto__ === Object.prototype ? true
[11] 普通函数有 prototype? object
[12] 箭头函数 prototype: undefined
[13] new 箭头函数会怎样: TypeError: arrow is not a constructor
```

- **函数有 `__proto__` 链**（指向 `Function.prototype`），同时**有 `prototype` 属性**（`new` 时给实例用）——`__proto__` 和 `prototype` 是两个不同的东西！
- **箭头函数没有 `prototype`**（不能 `new`，实测抛 `TypeError`），但它有 `__proto__`（是普通对象）。
- 所以链的完整路径：`p → Person.prototype → Object.prototype → null`；`Person → Function.prototype → Object.prototype → null`。

### 2.5 instanceof 与 Object.create

```
[6] p instanceof Person ? true   [7] p instanceof Object ? true
[18] ma instanceof MyArray ? true  [19] ma instanceof Array ? true
[21] obj.__proto__ === proto ? true  [23] obj.hasOwnProperty("greet") ? false
```

- **`a instanceof B` = 检查 `B.prototype` 是否在 `a` 的 `__proto__` 链上**（不是"由 B 创建"）。所以 `p instanceof Object` 也为 true（链上有 Object.prototype）。
- `Object.create(proto)` **显式指定原型**：`obj.__proto__ === proto`，`greet` 来自原型、不在自身。
- `Object.create(null)` 创建**无原型**对象：没有 `toString` 等任何方法（实测 `typeof obj.toString === 'undefined'`）——真·空对象，常用作安全字典（不会被原型污染）。

## 3. 继承：5 种方式的演进与坑（实测）

> 核心问题只有一个：**怎么把"子类的 prototype"接到"父类的原型链"上**，同时让**实例属性独立**、**方法复用**、**父构造只调一次**。下面 5 种是逐层修复前一种的缺陷。

### 3.1 原型链继承：`子.prototype = 父实例`

```js
function Animal() { this.colors = ['red', 'green']; }
Animal.prototype.eat = function () { return 'eating'; };
function Dog() {}
Dog.prototype = new Animal();   // 关键：把父实例当子类的原型
Dog.prototype.constructor = Dog; // 修复 constructor（否则指向 Animal）
```

```
[1] d1.eat() = eating                    ✅ 方法来自父原型
[2] d1 instanceof Dog ? true | instanceof Animal ? true   ✅
[3] 🚨 d1.colors.push('blue') 后 d2.colors = [ 'red', 'green', 'blue' ]
[4] d1.hasOwnProperty("colors") ? false  ← colors 在父实例上，不在 d1 自身
```

- **致命坑：引用类型属性被所有实例共享**。`colors` 数组挂在父实例（= 子类的原型）上，`d1` 改它、`d2` 也变。
- 原因：`Dog.prototype = new Animal()` 让**所有 Dog 实例共享同一个 Animal 实例**，实例属性全在原型上。
- 已废弃，仅用于理解原理。

### 3.2 构造函数继承：`Parent.call(this)`

```js
function Dog2() { Animal2.call(this); }   // 把父的实例属性复制到 this
```

```
[5] e1.colors = [ 'red','green','blue' ] | e2.colors = [ 'red','green' ]   ✅ 属性独立
[6] 🚨 e1.eat = undefined   ← 父原型方法拿不到！
[7] e1 instanceof Animal2 ? false          ← 不是 Animal2 实例！
```

- 修复了引用共享（属性独立），但**方法无法复用**（父的原型方法不在子实例链上，`e1.eat` 是 undefined），且 `instanceof Animal2` 为 false（原型链没接上）。
- 已废弃。

### 3.3 组合继承：`call` + 原型链（两者结合）

```js
function Dog3(name) { Animal3.call(this, name); }  // 第一次调父构造（实例属性）
Dog3.prototype = new Animal3();                    // 第二次调父构造（接原型链）
Dog3.prototype.constructor = Dog3;
```

```
[8]  c1.eat() = 旺财 eating      ✅ 方法复用
[9]  c1 instanceof Dog3 ? true | instanceof Animal3 ? true   ✅ 两个都 true
[10] 🚨 父构造被调 2 次: c1.hasOwnProperty("name") = true | Dog3.prototype.hasOwnProperty("name") = true
```

- 属性独立 + 方法复用 + instanceof 正确，**但父构造函数被调了 2 次**：`call` 一次（给实例），`new Animal3()` 一次（给原型）——原型上残留**多余属性**（`Dog3.prototype.name` 永远存在且是垃圾值）。
- 最常用但非最优。

### 3.4 寄生组合继承：`Object.create` 切掉第二次调用（ES5 最优）

```js
function Dog4(name) { Animal4.call(this, name); }       // 只调一次父构造
Dog4.prototype = Object.create(Animal4.prototype);      // 复制原型，不 new 父实例
Dog4.prototype.constructor = Dog4;
```

```
[11] d4.eat() = 小黑 eating      ✅ 方法复用
[12] d4.hasOwnProperty("name") = true | Dog4.prototype.hasOwnProperty("name") = false  ✅ 原型无多余属性
[13] d4 instanceof Dog4 ? true | instanceof Animal4 ? true   ✅
[14] Dog4.prototype.__proto__ === Animal4.prototype ? true   ✅ 链接对了
```

- **`Object.create(Animal4.prototype)` 只复制原型对象，不执行父构造函数** → 父构造只调 1 次、原型干净、instanceof 正确、方法复用。**ES5 时代的最优解**（很多库的继承实现就是它）。

### 3.5 class 继承：ES6 语法糖

```js
class Animal5 { constructor(name) { this.name = name; } eat() { return this.name + ' eating'; } }
class Dog5 extends Animal5 {
  constructor(name, breed) { super(name); this.breed = breed; }  // 必须先 super()
  bark() { return '汪汪'; }
}
```

```
[15] d5.eat() = 大黄 eating     ✅ 继承方法
[16] d5.bark() = 汪汪            ✅ 子类自己的方法
[17] d5 instanceof Dog5 ? true | instanceof Animal5 ? true   ✅
[18] Object.getPrototypeOf(Dog5) === Animal5 ? true   ✅ 静态方法也能继承
[19] 不调 super: ReferenceError: Must call super constructor in derived class before accessing 'this'
```

- **`extends` 底层就是寄生组合继承**（`Object.create` 接原型链），只是语言层面包装成 class。
- 两个 class 特有的规则：**必须先 `super()` 才能用 `this`**（实测忘调 super 抛 `ReferenceError`）；**静态方法也继承**（`Object.getPrototypeOf(Dog5) === Animal5`，因为 `Dog5.__proto__` 也指向 `Animal5`）。
- **现代开发一律用 class**；面试被问"手写继承"时才需要写出 ES5 寄生组合继承。

### 3.6 五种方式对比表

| 方式 | 属性独立 | 方法复用 | instanceof | 父构造调用次数 | 结论 |
| ---- | -------- | -------- | ---------- | -------------- | ---- |
| 原型链继承 | ❌ 共享 | ✅ | ✅ | 1（new 父实例） | 引用共享致命，废弃 |
| 构造函数继承 | ✅ | ❌ 拿不到 | ❌ | 1（call） | 方法复用失败，废弃 |
| 组合继承 | ✅ | ✅ | ✅ | **2 次**（call + new） | 有冗余属性 |
| **寄生组合继承** | ✅ | ✅ | ✅ | **1 次**（call） | **ES5 最优** |
| **class extends** | ✅ | ✅ | ✅ | 1 次（super） | **现代标准** |

## 4. 深入：为什么这样设计？

### 4.1 为什么属性查找要"沿链向上"而不是"复制一份"

如果每次继承都复制父的属性到子（像 Java 编译期那样），那**运行时就无法给父类加方法并让所有子类看到**。JS 选择"**共享原型对象 + 查找时沿链走**"，换来的是极致的动态性：

- 给 `Person.prototype.sayHi = ...` 加方法，**已创建的实例立刻能用**（不用重新 new）。
- 代价：查找要沿链走（比直接访问慢一点），但 V8 用 **隐藏类（hidden class）+ 内联缓存（IC）** 优化，实际开销极小。
- 这是"**共享**"而非"复制"——所以修改原型上的引用类型属性会影响所有实例（3.1 的坑根源）。

### 4.2 为什么 `__proto__` 和 `prototype` 是两个东西

这是 JS 新手最绕的点：

- **`prototype`**：**只有函数有**。它是"用这个函数 `new` 出来的实例的原型"（`new` 时实例的 `__proto__` 指向它）。可以理解为"**给未来实例准备的属性包**"。
- **`__proto__`**：**每个对象都有**。它指向"这个对象的原型"，构成链。函数作为对象也有 `__proto__`（指向 `Function.prototype`），但它自己的 `prototype` 是给**别的**对象用的。
- 命名之殇：Brendan Eich 最初叫它 `__proto__`（2008 年 Firefox 先实现，后来进 ES6 规范），规范术语是 `[[Prototype]]`，推荐用 `Object.getPrototypeOf()` 读取。

### 4.3 为什么 `constructor` 需要手动修复

`Dog.prototype = new Animal()` 之后，`Dog.prototype` 变成了一个 Animal 实例，它的 `constructor`（来自 `Animal.prototype`）指向 **Animal** 而不是 Dog。所以需要手动 `Dog.prototype.constructor = Dog`。不修的话，`d.constructor` 会指向 Animal（沿链找到的），导致用 `d.constructor` 创建新对象时得到的是父类实例——**静默 bug**。这是"原型继承"这种手工接链方式最容易漏的一步，也解释了为什么 class 语法糖更安全（语言自动维护 `constructor`）。

### 4.4 为什么 class 要求先 `super()` 再 `this`

ES6 的 class 继承中，子类实例的创建是**先建父类实例、再在上面扩展**（底层 `this` 由父构造初始化）。所以子构造里**访问 `this` 之前必须 `super()`**（实测：忘调直接 `ReferenceError`）——这不同于 ES5 的"先有 this 再 call 父"，是 class 更严格的初始化顺序保证。

## 5. 面试速记

> **30 秒版**："JS 用原型链实现继承：每个对象有 `__proto__` 指向构造函数的 `prototype`，属性访问沿链向上找直到 null。三个概念别混：`prototype` 只有函数有（new 时给实例当原型），`__proto__` 每个对象都有（构成链），`constructor` 在原型上指回构造函数。继承本质是接原型链：ES5 最优是寄生组合继承（`Parent.call(this)` 拿属性 + `Object.create(父.prototype)` 接链，父构造只调一次）；ES6 的 `class extends` 就是它的语法糖，且必须先 `super()` 才能用 this。实测原型链继承的坑是引用共享、构造继承的坑是方法拿不到、组合继承父构造调两次。"
>
> **追问版**："`instanceof` 查的是 `B.prototype` 在不在 `a` 的 `__proto__` 链上；`Object.create(null)` 能造无原型对象，适合当安全字典防原型污染；箭头函数没有 `prototype` 不能 new；函数也是对象所以有两条链（`Person → Function.prototype → Object.prototype`）。"
